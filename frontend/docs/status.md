## 1. 已交付内容

| 层 | 文件 | 说明 |
|---|---|---|
| 接口层 | `src/api/`（8 个） | 请求发送与错误归一、查询键工厂、健康检查、会话与消息、社群目录与建立、管理查询、契约生成的类型 |
| 身份 | `src/identity/`（2 个） | 当前主体的单一来源与订阅 hook |
| 纯逻辑 | `src/lib/`（4 个 + 4 个测试） | 角色配色与气泡拆分、消息分组、轮次状态推导、幂等标识 |
| 组件 | `src/components/`（14 个 + 1 个测试） | 头像、气泡、分组、输入器、状态栏、外壳、页面外框、页面控件、管理端展示组件、空状态、错误展示、路由级错误边界 |
| 用户端页面 | `src/app/`（8 个） | 身份登记、社群、角色、聊天、游戏列表 |
| 管理端页面 | `src/admin/`（9 个） | 运行状态、后端连接、社群总览、社群诊断、会话诊断、角色诊断、任务诊断、玩家 |

用户端三个主体页承担全部数据建立：注册玩家、创建或加入社群、从模板创建角色。管理端只读查询覆盖 `/internal` 的全部 32 个端点，按管理接入文档组织。

技术栈：React 19.3、TypeScript 5.9、Vite 8.3、React Router 7.18、TanStack Query 5.104、Tailwind CSS 4.3；测试使用 Vitest 5.0、Testing Library 16.3 与 Playwright 1.63。字体为 Inter 与 Noto Sans SC，自托管于 `public/fonts`。

**已人工确认**：四个字体文件全部加载；聊天页层次、气泡底色与未读标记按预期呈现；三个主体页与五个管理端页面在真实数据下可读，控制台无错误。

## 3. 本轮修正的问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 消息显示发送者标识而非名称 | 组件从 `sender.actor_id` 取名 | 改用消息携带的 `sender_display` |
| 已读推进无效 | `/read` 只有 `PUT`，此前用它读取 | 改用会话摘要的 `last_read_sequence` |
| 提及提交被拒 | 把展示用身份键当作 `actor_id` | 提交契约要求的参与者引用 |
| 私聊创建被拒 | 参与者未包含发起人 | 发起人始终加入，对方只列角色 |
| 填入的玩家标识一律 404 | 注册接口只写了接口层 | 入口页先确认玩家是否存在 |
| 主体页高亮「聊天」 | 主体页复用了聊天区域标识 | 主体页不显示窄栏，应用名作为回聊天入口 |
| 追踪查询 404 | 玩家消息用玩家标识限定角色 | 只有角色消息才限定角色 |
| 会话列表「下一序号」为空 | 列表项不携带该字段 | 列表改显成员版本，详情仍显下一序号 |

## 5. 当前限制

| 事项 | 说明 |
| --- | --- |
| 玩家身份 | 后端没有账户认证，当前主体保存在本地存储，是本地测试身份 |
| 群聊列表名称 | 摘要无名称字段，列表显示会话标识 |
| 管理员端访问边界 | 无服务端访问控制，服务只监听 127.0.0.1，页面不做访问控制 |
| 实时性 | 只有轮询，没有推送或逐字输出接口；消息轮询 4 秒，会话列表 8 秒，管理端 15 秒 |
| 角色显示名 | 全部实例共用模板显示名，同模板的多个角色在界面上同名 |
| 活动界面 | 阶段五接入，当前不预建渲染结构 |
