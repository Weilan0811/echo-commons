## 3. 验证范围

以下检查已实际执行并通过：

| 检查 | 命令 | 结果 |
|---|---|---|
| 类型生成 | `npm run api:types` | 从后端契约生成 1131 行类型，含 17 个操作与 19 个具名数据类型 |
| 类型检查 | `npm run typecheck` | 通过，无错误 |
| 单元测试 | `npm test` | 7 项通过，覆盖成功、`error` 信封、422 字段错误、网络不可达、503 可重试、查询参数跳过 |
| 生产构建 | `npm run build` | 通过，77 个模块，产物约 356 KB（gzip 112 KB） |
| 端到端测试 | `npm run test:e2e` | 4 项通过，真实 Chrome 与真实后端 |

联调确认的事实：

- 后端 `/health/live` 返回 `{"status":"ok","service":"echo-commons-server","version":"0.1.0"}`，页面显示的服务名与版本来自真实响应。
- 后端 `/health/ready` 返回 `database` 为布尔、`workers` 为名称到状态的映射（8 个进程），页面逐项列出。
- 跨域按后端 `cors_origins` 生效：放行 `http://localhost:5173`，其他来源不返回放行头。**访问前端必须用 `localhost:5173`**，用 `127.0.0.1:5173` 会被后端拒绝。
- 后端不可达时，存活与就绪各自独立显示归一后的中文错误提示，页面不空白。

端到端测试使用系统已安装的 Chrome（Playwright `channel: 'chrome'`），不下载浏览器。本机无法访问 Playwright 下载源，`npx playwright install chromium` 会失败。

### 联调发现并修复的缺陷

`/health/ready` 的 `workers` 是对象、`database` 是布尔，两者都曾按字符串处理：前者导致页面渲染崩溃（React 抛出「Objects are not valid as a React child」），后者导致该项渲染为空白。

同时补上了路由级错误边界。崩溃时页面原本显示 React 的内部报错与开发提示，对使用者不可用；现在显示可读信息并提供返回入口。

## 4. 当前限制

| 事项 | 说明 |
|---|---|
| 玩家身份 | 后端没有账户认证，页面中的玩家选择将是本地测试身份 |
| 管理员端访问边界 | 当前无服务端访问控制，远程真人测试前需按部署方式明确 |
| 实时性 | 只有轮询，没有推送或逐字输出接口 |
| 社群与会话发现 | 后端缺少玩家维度的发现接口，见 [接口缺口](02-backend-interface-gaps.md) 的 P1 |
| 活动界面 | 阶段五接入，当前不预建渲染结构 |
| Radix 基元 | 尚未安装。需要对话框、下拉或滚动区时再引入 |
| 后端运行环境 | 分支工作树的 `.venv` 入口不可用，联调使用主工作树启动的后端 |
