用户端三个主体页承担注册玩家、创建或加入社群、创作角色。管理端提供 `/internal` 诊断查询及测试社群清理入口。

角色页提供两条创建路径：从模板创建（简单记忆模式）与全屏「人物志」自定义创作。自定义创作的草稿与已固定人物跟随玩家身份、不绑定社群，角色页按当前社群实例、我的草稿、我创作的人物三个维度分区，草稿与人物列表游标分页。固定后的人物可在任意所在社群以简单或完整模式入住，模式创建后不可切换。角色页面展示准备中、失败与可用状态，准备中自动刷新，失败提供正式重试入口；新建会话同时检查角色可用状态与记忆准备状态。

历史消息通过分页查询缓存保留，增量读取推进扫描位置并读取全部积压，合并时按消息编号去重、按序号排序。同一次发送失败后保留请求编号及内容，修改内容后分配新编号；已读提交立即刷新当前玩家的会话列表。

会话列表与标题统一使用后端的 `display_name`。角色一次回应里的换行按独立气泡依次入场，延迟由前文长度累加并设单段上限；进入会话时已存在的消息一次全部出现，不重播入场。管理端按正式类型区分发言与沉默，分别展示发言、内心正文及清除时间，并保留可展开的运行详情；具体契约见 [管理接口参考](../../server/docs/reference/management-api.md)。

技术栈：React 19.3、TypeScript 5.9、Vite 8.3、React Router 7.18、TanStack Query 5.104、Tailwind CSS 4.3；测试使用 Vitest 5.0、Testing Library 16.3 与 Playwright 1.63。字体为 Inter 与 Noto Sans SC，自托管于 `public/fonts`。

## 3. 本轮修正的问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 消息显示发送者标识而非名称 | 组件从 `sender.actor_id` 取名 | 改用消息携带的 `sender_display` |
| 已读推进无效 | `/read` 只有 `PUT`，此前用它读取 | 改用会话摘要的 `last_read_sequence` |
| 提及提交被拒 | 把展示用身份键当作 `actor_id` | 提交契约要求的参与者引用 |
| 私聊创建被拒 | 参与者未包含发起人 | 发起人始终加入，对方只列角色 |
| 填入的玩家标识一律 404 | 注册接口只写了接口层 | 入口页先确认玩家是否存在 |
| 主体页高亮「聊天」 | 主体页复用了聊天区域标识 | 主体页不显示窄栏，应用名作为回聊天入口 |
| 追踪查询 404 | 玩家消息用玩家标识限定角色 | 只有角色消息才限定角色 |
| 会话列表「下一序号」为空 | 列表项不携带该字段 | 列表改显成员版本，详情仍显下一序号 |
