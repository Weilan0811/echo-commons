# 单个应用与两套路由树

状态：生效。适用于构建配置、路由与部署。

## 决定

用户端与管理员端是同一个前端应用中的两套路由树：`/app/*` 与 `/admin/*`。各自有独立布局与导航，管理员端路由按需加载。

共用接口客户端、通用组件、主题与状态处理。

## 实际影响

构建产物是一个静态目录，部署只有一份。接口地址、Node 版本、CORS 配置都只需处理一次。

两端的展示范围差异由布局和路由体现：管理员端可以看到任务、执行追踪和诊断，用户端不引用这些接口路径。当前不存在服务端访问控制，因此两端的可达性差异只体现在界面上。

## 背景与成立条件

后端是本地单进程服务，配置入口只有一处。为两个信息范围不同的界面维护两套构建产物和两份配置，会让部署与接口地址配置翻倍，而当前的差异仅是页面集合。

按需加载保证管理员端代码不进入用户端首屏产物，两者的实现依赖也不会互相牵连。

若将来管理员端需要独立认证、独立域名或独立发布节奏，拆分为单独应用是可行路径；在当前形态下提前拆分没有收益。

## 维护影响

新增页面时先判断归属：属于最终用户日常使用的进入用户端树，属于测试管理与运行事实查看的进入管理员端树。两棵树之间不共享页面组件。

跨端复用只通过 `src/components/` 和 `src/api/` 进行，不通过互相导入路由。

隐藏导航或隐藏入口不承担访问控制。远程真人测试前的访问边界按部署方式处理，相关约束见 [技术选型](../01-tech-selection.md) 的部署形态一节。
