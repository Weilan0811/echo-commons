# 小游戏产品策划

更新日期：2026-11-22。基础玩法已经实现，本文同时保留体验目标和扩展设想。三款游戏支持真人参与，五子棋和飞行棋支持角色行动与经历整理；飞行棋道具和 Kingdomino 事件卡属于尚未实现的设计方向。当前能力见[后端状态](../../server/docs/status.md)，规则来源见各玩法的基础规则文档。

## 1. 体验目标

让真人与角色在明确规则下共同游戏，边玩边交流，并在以后记得实际发生的共同经历。

游戏具有真实的合法操作、胜负和结算，角色作为玩家参与。人格影响风险偏好、竞争方式和说话习惯；胜负由规则与实际操作决定。游戏不直接改写人格或关系分数。

## 2. 玩法与顺序

| 玩法 | 目标 | 规则阶段 |
|---|---|---|
| 五子棋 | 完成真人对局、角色行动、局内聊天与经历保存的共同基础 | 15×15 自由规则，细则见开发计划 |
| 飞行棋 | 支持多人轮序、随机结果、路径移动和动画 | 明确来源的传统基础规则；随后增加随机刷新、拾取、保存和使用道具 |
| Kingdomino（多米诺王国） | 支持动态轮序、地块选择、摆放和长期规划 | 官方基础规则；随后设计回合间事件卡 |

飞行棋当前采用[基础规则文档](飞行棋基础规则.md)中固定的传统规则。事件卡的公开或私人选择、即时或保存生效仍待完整设计，不作为已确定玩法。官方扩展与已有产品案例的调查保存在开发计划中。

基础 Kingdomino 的王国和选块信息公开，长期规划不需要私人手牌；进阶规则采用私人选择时，再增加相应观察范围。

## 3. 一边游戏，一边交流

每场对局有独立的局内会话，参与者与本局席位关联；普通群聊和私聊继续使用自己的会话。游戏行动遵守轮序，玩家发言可以引起其他参与角色接话。

当前实现范围包含玩家发言后角色回应、角色行动时选择动作并决定是否附带发言。单选抽样、多选联合调用、同一角色的来源合并与恢复统一见[角色活动设计](../../server/docs/design/activity-integration.md)，不另设一套轻量策略替代多选模型决策。

界面同时展示棋局、当前行动者、实际合法操作与本局聊天。游戏结算后保留赛后交流，明确结束活动后保留只读历史。

## 4. 游戏经历

游戏保存完整对局、正式事件与结果，会话保存正式发言。角色保存实际生成的简短判断和感受，并按既有记忆模式选择值得长期保留的信息。自动执行的操作不补造内心记录，每一步棋也不全部复制成长期记忆。

共同经历可以包含竞争、合作、承诺、关键选择与结果。长期事实、主观认识和关系态度继续通过各自有来源的流程形成。

## 5. 开发安排

三款基础玩法、五子棋与飞行棋的角色活动已接入。后续扩展复用[共同基础](共同基础与文件结构.md)中的职责和接口；历史分工与实施顺序保留在[并行开发计划](../archive/gameplay/并行开发计划.md)。
