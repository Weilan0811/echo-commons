# 任务 9：新接口、开发工具与打包

状态：阶段完成。阶段要求见 [任务 9](03-backend-implementation-plan.md#11-任务-9新接口开发工具与打包)。本阶段建立独立本地提交。

## 已完成

新 HTTP 接入社群、玩家、人物模板、角色实例、会话、成员区间、消息与轮次，路由直接调用正式业务服务。请求使用下划线字段，拒绝未知字段；请求模型、领域对象和响应模型分别定义并明确转换。错误通过稳定的 JSON 结构返回，存储异常不返回内部错误内容。

公开响应使用独立展示类型。轮次查询通过共同的角色观察规则验证读取玩家及输入消息的可见范围；私有输入的轮次只向完整受众开放。内部上下文与反思查询检查社群和角色归属，追踪统一查询已投递记录与待投递记录。就绪状态读取数据库迁移记录与实际后台执行状态。

CLI（开发命令）提供 `configure`、`init`、`inspect`、`export` 和 `serve`。初始化及多人示例复用正式业务服务；检查和导出使用只读数据库连接，缺失数据库不会被创建；导出使用 SQLite backup 保存一致副本。生成配置和导出均拒绝覆盖已有文件。

配置模板、SQL、人物资源和两名玩家、两个独立角色的 JSON 示例全部随安装包提供。显式配置中的相对路径从设置文件所在目录解析，人物资源默认从包中加载。密钥文件由用户配置，不进入发布包。安装验证工具为 `server/tools/verify_installed.py`。

CORS（浏览器跨站请求规则）允许本阶段需要的 GET、POST、PUT、PATCH 和 DELETE 方法；来源继续由配置给出。旧消息路径没有接入新应用。

## 验证结果与自行审核

真实 HTTP 验证使用正式应用生命周期与 SQLite：重复请求返回原结果，内容冲突返回 409，缺失对象返回 404，旧字段返回 422，旧消息路径返回 404。私有消息、玩家游标、离开后重新加入、私有轮次、内部上下文范围均通过验证。

正式 HTTP 真实模型场景通过：两名玩家与两个小槿实例通过接口创建，玩家发言触发两个角色的实际模型请求，两个角色分别提交非空回应，轮次完成，另一名玩家读取回应，数据库外键检查通过，退出后模型客户端和后台执行器关闭。

开发命令在独立子进程中通过验证：生成配置、示例初始化、重复初始化、只读检查、一致性导出、拒绝覆盖和拒绝只读创建缺失数据库。非模型基础测试共 80 项通过。本阶段 HTTP 与开发命令测试共 6 项，其中 1 项调用真实模型。

`uv build` 生成 `0.1.0` 源码包与安装包；在源码目录外的新虚拟环境安装后，生成配置、初始化完整示例并执行安装验证工具。模型实际返回两个角色回应，轮次完成，SQL 与配置资源完整，外键错误为 0，客户端全部关闭。安装环境使用安装包中的 `site-packages/echo_commons`。

按模块检查通过 Ruff（代码检查）。审核重点为接口到服务的明确转换、玩家可见范围、角色诊断范围、只读命令行为及安装资源。原有用户数据与密钥未修改，未推送或发布。历史实现、失效文档与最终完整验收由任务 10 处理；严格保留的未完成能力仍按任务方案执行。
