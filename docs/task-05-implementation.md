## 关键规则

1. 自动规划只消费玩家的 sealed 批次，角色批次继续记录来源。不同可见性或实际受众分别规划；每个批次通过唯一关联只消费一次。
2. 每个轮次在自己的写事务内重新检查来源、社群状态、会话状态和执行中轮次。一次事务保存来源、参与决定、各角色快照和任务；模型调用不进入准备事务。
3. 候选排除已离开的角色、原受众之外的成员区间、当前不可回应角色和看不到全部来源的角色。提及优先；其余按最近发言时间和实例 ID 稳定选择，未发言角色优先。
4. 群聊最多选择两个角色，直接会话选择其唯一角色。未参与原因明确保存。全体沉默或没有角色时，轮次直接完成，不创建空任务。
5. 一个任务只属于一个轮次和角色实例，并保存当时的原成员区间。任务准备核对该区间确实属于对应角色，重新加入无法使用以前的受众区间。
6. 快照的客观观察来自 perspective；情绪、身体和活动自述及关系认识来自 characters；常驻记忆、检索来源及已有摘要来自 memory。自身状态不进入其他角色观察。
7. 快照保留精确输入和受预算限制的可见历史。人物名称、实例、模板正文、独立资源版本、状态、关系、记忆、社群和成员版本都保存明确来源。关系材料只包括可见人物和本角色已有关系认识中的对象。
8. 任务保存完整 JSON 快照；执行状态更新、挂起和恢复不修改快照。对话用途只允许正式角色发言契约，工具根据实际能力交集确定。
9. 调度时沉默没有任务；被选角色后续沉默、失败、完成或取消由参与记录表达。只要仍有 selected 参与者，轮次继续执行；全部成为终态后保存各结果数量。
10. 模块材料策略使用独立标准数据对象，不依赖应用入口或整份配置。输入收集规则已从 Repository 移至业务服务，Repository 负责具体存储。

## 自行审核

- 核对来源通过消息 ID 关联，交错发送不会补入其他主体消息。
- 核对一会话一执行中轮次、同轮次同角色一任务，以及原成员区间检查。
- 核对重复及并行规划在写事务内重新检查来源，不重复创建轮次、任务或快照。
- 核对来源版本只包含实际使用或允许检索的可见材料，人物资源使用自己的内容版本。
- 核对每个角色的私有记忆和状态分别读取；后续状态变化与输入不改变已保存材料。
- 核对挂起、恢复、取消和参与完成的存储操作保持快照，取消后的轮次能够结束并继续规划后续输入。
