本轮属于静态源码核查，没有启动旧服务或调用模型。完整请求还包含随玩家消息、角色状态和来源改变的数据；本轮没有声称新旧运行生成的完整请求已经逐字一致。已确认的固定文字和组装差异，足以判定本项要求未满足。

## 3. P0 待修改差异

以下各项均未修正。编号用于定位范围，优先级相同。完整原文以证据目录中的原始文件为准。

### P0-01：对话输出说明被替换

原实现的 `render_output_contract` 明确解释 thought、utterance、换行、空内心片段及禁止额外输出。当前 `conversations/tasks/prompt.py` 使用 JSON Schema（字段结构说明）和几句简短说明替代这些内容。

丢失内容包括：thought 只记录当下真实出现的念头；没有念头可以为空；不承担回复计划、对话分析、模型推理或规则说明；utterance 承担真正回应；换行对应真实停顿且不应额外补话。

当前还增加 `reply_to_message_id`、`outcome=silent` 和完整结构说明。它们是新旧模型契约的可见差异，应逐项明确需要的扩展及原文保留方式，不能因为属于新结构就自动视为符合逐字要求。

### P0-02：七段对话表达指导全部缺失

原实现 `render_conversation_guidance` 的七段文字，没有逐字迁入当前对话提示。

原规则完整覆盖：从当下生活、记忆和感受出发；按实际内容决定长短；短回复不必扩展成长话题；thought 可以不完整、犹豫或与说出口的话不同；避免客服式表达和套用共情；有实际问题才追问；人物设定自然出现；不要重复上一轮开头、句式和问法。

这些文字直接影响角色说话方式，应恢复原文。重写成简短原则会继续丢失经过打磨的表达约束。

### P0-03：人物规则的共同说明和注入方式改变

原 `render_agent_contract` 在资源正文前加入一段共同说明，明确角色身份、记忆、能力和表达规则适用于 utterance、thought、reflection 全部输出字段。当前该段没有保留。

原身份资源分别放入 `<agent_contract>`、`<character_profile>`、`<character_relational_dynamics>`、`<character_voice>` 段落。当前将正文作为自身信息对象的字符串值，再序列化为 JSON，换行、引号及段落边界的模型可见形式改变。

原反思调用 `render_identity_sections(..., include_voice=False)`，当前将包含 voice 的完整 SelfContext 发送给模型。资源正文一致与最终注入一致需要分别验收。

### P0-04：记忆、状态、关系、环境及历史表达改变

原 `render_resident_memory`、`render_recalled_memory`、`render_session_digest`、`render_active_threads`、`render_character_state`、`render_relationship_state`、`render_situation` 的自然语言标题和句式没有保留。

原对话按明确段落组合核心记忆、当前状态、关系、连续性、取回记忆、未完成事项和情境。当前主要输出 self、memory、environment、public_facts 对象的 JSON，包含新的字段和标识信息。

原玩家历史以正文传入；角色历史在适用时包含对应 thought、utterance。当前把整个 ObservedMessage 序列化，并且没有对话历史 Thought。后一项也登记于 D01。

多角色身份区分是当前设计的需要；旧文字删除、历史信息缺少和格式变化仍应独立记录，不能一起视为已经完成迁移。

### P0-05：共同反思规则与来源解释丢失、改变

原 `render_output_contract` 要求回看真实经历、保留不确定、正文使用角色第一人称，并区分本次证据与背景。当前简短说明没有完整保留。

原明确写道：

> evidence_refs 只填写输入中显示、且属于当前节点允许范围的来源字符串，例如 message:<id> 或 thought:<id>。前置 Artifact 可以帮助理解，但不能替代本次来源引用。

当前提示将前驱产物与本批材料共同称作事实依据，并将 `artifact:<id>` 加入可引用列表。来源角色改变需要按节点核查，不能以文字缩写掩盖。

原 `_MEMORY_ORGANIZE_SOURCE_GUIDANCE` 对来源类别有明确解释：玩家的话证明玩家这样说过；角色消息证明角色说过；Thought 提供当时的注意、感受或判断；已审核摘要提供整体背景。常驻记忆不能作为本次证据，内容不完整也不能证明当前内容一定是新的。当前未保留这两段完整说明。

### P0-06：段摘要的职责、细则及示例丢失

原 `segment_summary_plan` 说明要求摘要写真实发生的事情及当时感受，保留细节和没有说完的部分，使用第一人称，停留在经历本身，避免提前下关系结论。

原进一步要求消息与 Thought 一起阅读，回复计划、猜想、规则说明不能成为已发生事实；follow_up 只代表值得继续分析。当前只有“整理本记忆段”与继续分析的简短说明，原示例和完整规则没有保留。

### P0-07：关系反思的三维判断规则丢失

原 `relationship_reflect` 对 affection（好感）、trust（信任）、attachment（依恋）分别给出具体条件，明确负向变化的材料要求及 level（本次变化幅度）的含义。

例如原文明确规定：

> 普通聊天、一次关心、顺畅接话、习惯聊天或想起对方，本身不足以支持 attachment。

当前提示只要求按目标与维度处理有依据的变化，缺少原判断细则、幅度条件及示例。新增 target 确定多角色关系对象的用途清楚，但不能代替这些规则。

### P0-08：状态反思的表达和边界细则丢失

原 `state_reflect` 要求从 physical、mood、activity 中选择一种，使用第一人称的一两句具体当下体验，只写状态本身；时间、有效期、版本和数据库标识由运行层管理。

当前仅说明填写材料支持的自身状态变化，原表达细则、示例及无可靠信号的处理说明没有保留。

### P0-09：连续性压缩规则丢失，并出现相反指令

原 `continuity_compress` 说明如何使用前一摘要与当前段摘要、如何更新变化、保留哪些长期信息、删除哪些重复内容、如何使用第一人称及填写精确覆盖范围，包含完整示例。

原文明确要求：

> 本图已经有冻结的摘要批次，只要当前材料存在，就必须返回 continuity_digest。不要返回 no_op。上一条摘要可以很短，当前批次仍然必须推进覆盖范围。

当前所有节点的共同提示允许 no_op，连续性节点的结构说明也包含 NoOpReflectionAction，缺少原逐图例外。该项是直接的指令冲突，与已登记的 D02 运行差异相关。

### P0-10：长期记忆页的生成细则丢失

原 `page_compose` 要求每条独立事实分别生成记忆页，同一事实重复出现时合并，只有需要共同回想的细节才合并。还有第一人称、主题范围、可信度、重要程度、本地实体键及证据支持每一条页的具体说明和多页示例。

原排除普通寒暄、一次性安排、未获角色支持的猜测与瞬间情绪。当前一句长期价值概括和字段结构说明没有保留这些判断规则。

### P0-11：记忆图提取的细则丢失

原 `graph_extract` 明确规定实体范围、稳定称呼、本次响应中的本地键、两端实体必须同时出现在输出、关系方向、重复实体与边处理、证据支持范围及运行层负责实体识别。

原明确说明两个实体同时出现不等于存在关系；不能仅引用常驻记忆中的对象；不输出数据库实体标识、别名记录或提交命令。当前简短提取说明与字段结构没有完整保留这些内容及示例。

### P0-12：记忆搜索的工具说明和返回表达改变

原正式工具说明为“在角色可见的长期记忆和相关对话中检索有限的记忆线索。”；当前改成“检索当前角色有权查看的过去消息与自身记忆。”。

原 query 的说明“想回想的主题、人物或事件”没有保留。参数结构、长度限制也改变。原结果使用 results、summary、sourceRef 等字段，当前改为 items、text、source_id 等字段；工具观察外壳也从 callId、errorCode 等改为对应下划线字段。

人物资源里的能力说明保留，但它无法证明正式工具定义一致。这些都是模型实际可见的差异。

### P0-13：部分格式修正和任务重试提示改变

`invalid_model_output` 原提示：

> 请只返回符合输出 Contract 的 JSON 对象，并补全所有必需字段。

当前提示：

> 请生成符合输出契约的业务结果 JSON 对象，填写行动类型、实际分析内容和所需证据，补全所有必需字段。

旧审核恢复分别提示缩短 thought、生成非空 utterance、缩短 utterance。当前长度重试改为共同提示“上次发言未通过长度审核，请缩短 thought 和 utterance。”，并新增调用前的长度说明。

其中六条格式或工具参数修正提示，以及 Harness 的工具进展提醒、修正外壳文字保留。保留与改变的部分应分别处理，避免全部重写。

### P0-14：字段结构、消息排布和请求参数差异

当前新增完整 JSON Schema 注入，旧反思输出示意与具体节点示例没有迁入。结构变更还包括关系 target、kind 是否有默认值、证据是否必填、关系维度数量范围及旧关系示例删除。

原反思把共同规则、节点职责、身份、状态、关系、材料和前驱分别作为消息传入，最后给出节点任务。当前合并为一条 system 和一条 user 消息，排列和角色归属发生变化。

供应商消息转换函数保留；请求参数对工具存在时的 response_format 处理发生改变，新增 silent 输出解析。后续应分别验收固定原文、扩展字段、上下文组装和请求协议，任何一项都不能由正常模型回复替代。

### P0-15：未接入反思任务的共同提示范围

原提示保留日记、视图正文的第一人称要求及备用节点说明。当前正式投影器只覆盖六类已接入节点，没有完整保留原共同提示范围。

后续恢复已有文字和契约记录时，应保持 `diary_compose`、`view_refresh` 的原实现边界。此项不要求实现当前尚未接入的触发、执行和消费流程。

## 4. 后续修正与验收

1. 从本地历史恢复已经打磨的固定文字，保留原标点、换行、例子和具体判断条件。
2. 单独列出多角色身份、关系目标、受众及输出字段所需的扩展。扩展不能静默重写原正文；涉及旧规则与新结构冲突时，给出具体原句和具体扩展供审核。
3. 按实际调用路径验证正文确实进入对话和反思请求，覆盖六类节点、工具调用、格式修正及任务重试。
4. 固定内容使用逐字断言；动态内容检查身份、来源、顺序及可见边界。使用正式资源、真实领域对象和正式投影器，禁止用模拟回复证明提示迁移。
5. 恢复提示之后，再通过真实模型场景检查角色表达和事实边界。模型生成正常不代表文字核查通过。

设计审核、代码修正、真实验证的既定顺序继续有效；当前仅提前确认并登记最高优先级差异。
