## 关键规则

1. 调用身份包含社群和角色，调用范围、任务记录及完整快照相互核对。一个实例的 Agent 拒绝另一个实例的调用。
2. 工具查询主体由执行器决定。模型参数只接受查询文字与数量，不能指定其他角色、社群或快照。
3. 工具上下文包含明确 scope、快照引用和读取策略。工具按照冻结时间、会话观察上限和角色自身来源版本读取；来源变化明确报告 `memory_source_changed`。
4. 工具定义必须由真实实现提供，允许列表中的工具缺失时明确报错。工具结果的调用身份必须与请求一致。
5. 历史中只有当前角色的发言使用 assistant 身份；其他玩家和角色保留自己的 ActorRef、名称与消息标识。
6. 输出包装器通过注入的注册表解析具体类型。对话调用要求 `character_message.v1`，空白发言无法通过校验。结果恢复时保留具体提案类型及全部字段。
7. 模型可以返回明确的沉默对象 `{"outcome":"silent"}`。执行循环产生 `no_proposal` 结果，实际参与完成及消息提交由任务 7 负责。
8. 执行循环处理已经定义的模型、工具和预算错误。未预期的程序错误保留原类型，由后台运行层记录和处理。
9. 工具启用时使用供应商正式函数调用协议；普通无工具请求继续使用配置中的 JSON 模式。最终内容始终经过同一输出契约校验。

## 自行审核

- 检查实例、调用身份、模型路由、快照来源及工具查询范围一致。
- 检查执行准备结束数据库读取后才调用模型，查询工具只在自己的短读取事务中访问数据库。
- 检查私有材料来自对应角色的可见来源，其他角色材料不会进入模型输入或查询结果。
- 检查旧账号绑定、旧快照投影、旧角色发言格式及工具兼容定义已移除。
- 检查通用输出解析不导入反思专有类型，反思用途及节点材料按任务 8 接入。
- 检查保存结果的恢复使用已注册类型，避免通用模型丢失具体提案字段。
