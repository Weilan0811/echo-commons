## 3. 原实现复核后的更正

原反思文档提出 partial 后创建恢复运行、复用成功产物的目标，但原 Coordinator 和 Executor 没有完整接入。因此 D03 归为继承的未实现能力，不在本轮代码修复中增加完整恢复入口。已实现的过期节点恢复和原 failed 图处理仍需核对保留。

原 StateFactHandler 在提交事务中读取最新记录，将其版本传给状态替换和存储。模型候选没有读取时版本。D04 不再要求新增该字段，也不把较早模型输入直接判作状态冲突；按原事务内版本、时间和有效期规则核查。

原关系消费者同样使用 interaction 证据，D07 保留原接入边界及纯领域资格算法，不新增支持或承诺分类器。

SocialTurn 为多角色新增对象，等待输入由 sealed 批次表达，原子规划直接创建 running 或 completed 轮次的实现可以保留。SQL 多出的 pending 允许值列入类型一致性修复。system 是原消息来源能力，与社群中的玩家、角色成员身份分别核查。
