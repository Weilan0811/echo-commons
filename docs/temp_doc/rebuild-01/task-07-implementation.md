## 实际结果

玩家消息可以由后台规划为轮次，两个角色分别执行真实模型、审核结果并提交完整发言。消息、批准结果、私有思考、角色输入批次、任务与参与状态在同一事务完成。成员变化、社群暂停、模型沉默和失败都有明确处理路径。

应用启动加载明确配置、模板和模型注册信息，初始化新数据库并管理工作器。启动不会创建默认社群、玩家或角色。

## 关键规则

1. 领取在短写事务中完成。同一任务只有一个有效租约，领取增加执行次数和租约代次。续期、提交和重新安排都检查当前所有者、次数、代次及有效期。
2. 模型和工具执行不持有数据库写事务。模型请求共享有限并发额度；规划和追踪不占用该额度。
3. 执行结果和任务身份必须相符。审核检查当前角色仍处于原成员区间、会话和社群可运行，以及输出契约和回复目标可见。
4. 其他成员变化不会整体作废仍有效角色的快照。批准发言沿用原轮次中仍有效的受众区间，新成员和重新加入形成的新区间不会补入旧受众。
5. 一次角色发言只有一条消息。其输入批次使用共同对象，窗口为零，并保存来源轮次及批准结果。角色批次不会启动无限自动接话。
6. 私有思考只保存到 thoughts；普通结果审计内容去除 thought。批准结果、消息、思考、角色批次、检索索引、任务、参与结果及追踪待投递记录在同一事务写入。
7. 沉默正常完成任务和参与结果，不插入空消息、空思考或角色批次。全部参与者成为终态后结束轮次。
8. 重复结果返回已经记录的处理结果。旧租约或已离开角色的迟到结果不能生成消息。
9. 社群暂停释放任务租约并挂起任务；恢复复用原快照。成员离开与会话归档取消相应任务并检查轮次完成。模型错误不会变成角色长期状态。
10. 临时错误按次数与退避预算重试；永久错误结束该角色参与。长度审核失败会在后续调用加入修正要求，快照保持原样。
11. 工作器关闭后停止领取，等待在途工作；超过关闭期限取消调用。未完成任务由真实到期租约恢复。供应商连接和应用日志句柄随应用关闭。
12. 追踪领取和投递分开处理，投递写入与待投递记录删除在同一事务完成。真实存储错误记录重试，达到上限后保留明确失败状态；不改变已提交的消息。
13. SQLite 错误只在存储边界转换，原错误通过异常来源保留。未预期程序错误保留类型与堆栈，普通日志不复制模型输入、私有思考或异常中包含的数据正文。

## 自行审核

- 检查模型调用与数据库事务的边界，以及并行任务各自独立的租约和快照。
- 检查批准结果唯一性、同次结果唯一性、同结果消息唯一性，以及完整提交的事务范围。
- 检查第一条角色消息产生后，第二个任务仍使用原快照并可正常完成。
- 检查受众区间、离开与重新加入、当前角色身份和迟到结果的处理。
- 检查挂起、取消、失败及沉默均有参与终态，轮次可以继续推进。
- 检查追踪写入失败与工作器失败具有真实状态，消息读取不依赖追踪投递。
- 检查默认数据没有创建，用户实验数据库和密钥没有修改。
