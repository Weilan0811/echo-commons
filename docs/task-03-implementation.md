## 关键规则

1. 创建角色时，在同一事务内写入实例、社群成员、三种初始状态和人物资源中的正式记忆。初始状态描述为空；预置记忆保持资源中的原有正文。
2. 模板中的自身引用解析为当前实例的 `character_id`。每份记忆使用自己的 ID，保留完整人物资源和内容版本来源。两个同模板实例相互独立。
3. 显式 ID 的重复登记检查原有内容。重复创建实例直接返回已有实例，不增加记忆、不重置状态；跨社群复用实例 ID 报告冲突。
4. 直接会话采用共同成员规则：恰好一个玩家和一个角色。群聊采用通用 ActorRef。成员只能引用已存在且属于该社群的主体。
5. 成员离开保存当时序号，重新加入创建新的区间 ID。历史区间和受众仍保留。成员变化结束正在收集的输入批次。
6. 最新状态条目过期后返回空状态，不恢复以前的状态值。状态来源重复提交比较内容；版本冲突明确报告。
7. 社群状态、角色可用状态仅在实际内容变化时增加版本。关系认识保持有向，朋友证据使用同一关系范围的复合外键。
8. 写事务不覆盖模型调用。迁移使用 SQLite 自带语句识别，在同一事务完成 SQL 和版本记录；失败回滚。并行初始化通过写事务重新检查版本，数据库切换日志模式的忙碌错误在存储边界有限重试。
