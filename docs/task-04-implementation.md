## 关键规则

1. 玩家发送时校验当前社群和会话成员身份。公开消息保存当前全部成员区间；私有消息保存合法接收者与发送者区间。
2. 回复目标必须对发送者可见，接收者和提及对象必须是当前会话成员。提及不会增加消息受众。
3. `(player_id, client_message_id)` 是幂等键。重复请求比较会话、正文、可见性、回复、提及顺序和原始接收主体。受众通过历史记录取得，发送者离开后仍返回此前已保存消息；不同内容报告冲突。
4. 可见性同时要求社群、会话、成员序号区间、观察上限和消息实际受众匹配。成员离开保留过去经历；重新加入采用新区间，间隔期间的消息继续不可见。
5. 玩家游标记录社群、会话、玩家与实际扫描位置。扫描到不可见消息也前进；响应可能没有可见消息，但仍返回新的扫描位置和是否还有材料。
6. 角色观察公开人物名称及参与身份。模板增加明确 `display_name` 字段，避免从私有人物正文推断公共名称。其他角色的情绪、关系和 Thought 没有观察读取入口。
7. 索引写入与重建只使用共同观察接口提供的可见来源。查询再次核对真实来源及内容版本，返回原始来源正文；失效记忆无法由残留全文投影恢复。
8. 检索范围携带社群、角色、准备时间和可选会话序号上限。准备后的消息与记忆不进入同一次冻结范围。有效来源列表采用标准 JSON 表示版本，不包含不可见消息；来源发生有效变化时明确报告。
9. 玩家批次使用安静窗口，到期批次先结束再接收后续消息。交错发送保留各主体自己的消息关联。角色提交将通过共同收集端口使用零窗口，真实角色结果接入任务 7。
10. 消息时间在取得写事务后生成，序号分配和消息提交处于同一事务。追踪普通载荷只包含身份、范围与序号等诊断信息，不保存消息正文。

## 自行审核与删减

- 核对正式消息入口没有账号同步、图片占位、客户端时间、界面建议或气泡编号。
- 核对公开和私有消息都保存实际受众，加入和重新加入不补写历史接收记录。
- 检索和角色观察直接复用同一条资格规则；源码中的旧分词文件已删除，剩余待适配记忆消费者引用唯一的新分词实现。
- 身份公开读取只提供名称，不向其他角色暴露模板私有正文或内部状态。
- 检查数据库事务与不可变领域对象；模型调用不在本阶段消息事务内。
