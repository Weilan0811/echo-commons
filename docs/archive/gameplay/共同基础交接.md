# 游戏与角色活动共同基础交接

更新日期：2026-10-29。当前基础已经提供真人五子棋、局内聊天、角色邀请与撤回、角色观察、玩法分析及活动输入与工作记忆。角色自动决策、局内接话和游戏记忆消费由后续角色活动开发接入。

## 1. 启动与安装

继续在 `server/` 执行 `uv sync`、`uv run echo-commons serve`，在 `frontend/` 执行 `npm install`、`npm run dev`。游戏包通过可编辑依赖加载同一工作树的 `games/`；服务端代码变化需要重新启动后端。一个正式应用使用一个后端进程、端口和 SQLite 文件。

部署安装时同时构建并安装 `games/` 与 `server/` 的 wheel（Python 安装包）。`server/tools/verify_games_installed.py` 用于安装环境中的实际启动、迁移、真人整局、聊天和实时通知检查，需在源码目录外执行。前端生成类型来自宿主 OpenAPI。

## 2. 业务入口

| 入口 | 职责 |
|---|---|
| `application.games` | 游戏包权威服务，处理规则、席位、机会、动作、回执和事件 |
| `application.game_participation` | 宿主参与服务，验证操作者并共同提交游戏与会话变更 |
| `application.game_queries` | 社群范围、房间及资格、实际参与访问上下文、公开候选与历史分页 |
| `application.game_observations` | 角色自己的参与发现、当前观察和原区间事件读取 |
| `application.conversations` | 会话成员、归档及相同连接内的业务方法 |

邀请沿用 `POST /api/games/{game_id}/participants`。`participant.kind=player` 表示当前真人自己，`kind=character` 需要角色编号，真实操作者仍由 `player_id` 确定。撤回沿用 `/leave`，目标取实际参与编号。请求和错误格式见[游戏接口](../../../server/docs/reference/game-api.md)。

创建者的角色邀请、游戏参与及局内成员在一个短写事务中保存。重试返回原请求的完成结果。等待时撤回释放角色席位和会话成员，重新邀请产生新区间；认输仍按原有真人本人资格执行。

## 3. 角色观察读取

在应用内调用：

```python
participations = application.game_observations.participations(
    community_id, character_id
)
observed = application.game_observations.observe(
    community_id, character_id, game_id,
    participation_id=participation_id,
)
```

`observed.context` 提供真实会话关联、游戏概要与 `SeatAccess`；`view` 提供角色可见局势及本人的合法机会，等待阶段为空；`events` 提供按该区间受众过滤的正式事件、扫描位置与后续标记；`observation` 是角色侧的 `ActivityObservation` 投影。观察时间来自实际游戏变化时间，内容中的游戏类型、规则、版本和事件编号来自正式记录。

`observe` 支持 `after_sequence` 与 `limit`，概要、视图和事件在同一只读事务读取。已撤回区间无法作为当前观察使用。历史通过 `events(community_id, character_id, game_id, participation_id, ...)` 读取，可指定版本上限；更换区间后保留各自扫描位置。观察服务通过注入的 `GameParticipationReader` 协议取得身份、社群和游戏关联，不依赖 HTTP 路由或直接查询游戏表。

## 4. 后续执行接入

2026-10-28 已接入五子棋玩法分析与可扩展候选接口，使用 `application.game_analysis.analyze(AnalysisRequest(...))`。游戏包公开只读战术和动作预览；Rapfi 运行资源、安装及验证见[玩法分析设计](../../../server/docs/design/game-analysis.md)。当前仍需后续单元接入角色任务和模型选择。

现有基础尚未注册角色活动的模型用途、输出提议、任务队列或记忆消费者。执行开发应复用实际观察、游戏公开动作方法和现有任务设施。规则及执行边界见[角色活动设计](../../../server/docs/design/activity-integration.md)。

2026-10-29 已提供 `application.activity_context` 的三种输入准备及 `activity_working_memory` 的局内意图存储。准备固定原参与区间、棋局与聊天截止，并保存人物投影和已完成的分析阶段；理解结果保存后推进处理位置。人物精简使用现有路由 `activity_persona`。实际接口和恢复范围见[活动输入设计](../../../server/docs/design/activity-context.md)，后台任务与自动清除联动继续由后续单元接通。

角色提交需要在同一个短写事务中复核实际任务租约与参与资格，调用游戏服务执行动作，通过会话业务方法保存获准发言，再提交任务结果。模型调用期间不持有写事务。完整目标中的来源合并、抽样恢复及游戏经历需要实际消费者接入后再声明完成。

## 5. 验证与已知限制

游戏、角色参与、持久化、历史隔离、原请求恢复和通知检查使用真实服务与数据库。相关测试位于 `server/tests/infrastructure/test_game_characters.py`、其他游戏基础测试及 `games/tests/`。前端真实恢复检查使用 `frontend/verification/game-operations.live.test.tsx`，通过 `VITE_API_BASE_URL` 指定隔离测试后端。

安装、旧库副本升级、整体验收和浏览器证据的实际结果见[后端状态](../../../server/docs/status.md)、[前端状态](../../../frontend/docs/status.md)。当前仅注册自由五子棋；角色自动行动、局内接话与游戏记忆尚未接入。手机实机软键盘仍未验证。
