# 决策模型游戏案例与实际能力

查阅日期：2026-10-18。本文保存可检查的一手资料及其适用边界；项目方案见[06 号设计与实施计划](../implementation/06-activity-implementation-plan.md)。这些公开结果没有在本项目环境重新运行。

## 1. 调研结论

可借鉴的共同结构是：程序或专用分析器计算局势、候选与后果，决策模型结合明确目标选择，生成模型处理开放表达和超出候选的问题。节省来自减少逐步文本生成，同时控制输入和候选规模。

合法动作、战术计算、人格选择和表达质量是不同能力。一个模型输出合法选项，不能证明它具备计算能力、长期目标连续性或可信的发言理由。

## 2. 五类游戏案例

### 2.1 Jev 国际象棋：输入表示决定了很大一部分效果

[作者的实验记录](https://github.com/wondertwins/jev-benchmark)使用 30 个局面与 25 个一步将杀题。原始棋盘表现很弱；程序提供局面及逐动作战术事实后明显改善，但整局仍暴露缺乏前瞻和计划的问题。实验规模较小，不能直接换算成本项目棋力。

[实际状态构造代码](https://github.com/wondertwins/jev-benchmark/blob/main/jevchess/state.py)使用 `python-chess` 计算走法后果，区分新暴露的棋子、解救、交换损失和对方下一步将杀；`tactical_description()` 优先描述损失，再提供其他差异。模型接收到的是可比较的动作说明。

项目启示：给每个空位一个坐标不足以支持便宜而可靠的五子棋决策。局面计算需要单独承担；措辞和候选内容也需要评价。

### 2.2 马里奥：便宜模型调用背后有实际模拟成本

[作者的完整对照](https://github.com/4esv/jev-mario)同时比较直接控制、实时控制和预模拟候选。预模拟版本可完成部分关卡，直接控制没有同等结果。作者记录每关约 25～35 次调用，同时需要约 15～20 分钟模拟；这组时间来自作者环境。

[`branch.py`](https://github.com/4esv/jev-mario/blob/main/branch.py)从同一个模拟器快照执行动作及后续分支，再描述存活、进度和后续可行性。动作菜单包含专门设计的组合操作；菜单不足时模型也无法找到菜单外的解法。

项目启示：需要同时计算本地分析耗时和模型耗时。缩短模型回答，不会自动缩短整个决策流程；候选遗漏必须有明确处理。

### 2.3 JevBall：候选、本地执行与分级调度

[项目说明](https://github.com/atarikcaliskan/jevball)把几何、物理和候选留在本地；模型选择带具体目标和特征的动作。不同球员采用不同决策频率，迟到或失败时使用本地策略，因此演示的连续运行也依赖程序策略。

已核对的关键代码：

- [`candidates.js`](https://github.com/atarikcaliskan/jevball/blob/main/src/candidates.js)：限制候选数量，同时保留不同动作类别与目标。
- [`jev-request.js`](https://github.com/atarikcaliskan/jevball/blob/main/src/jev-request.js)：紧凑描述选项，按问题需要提供局势，不把本地策略选中的答案当作事实提示模型。
- [`decision-loop.js`](https://github.com/atarikcaliskan/jevball/blob/main/src/decision-loop.js)：区分模型、本地规则、保留的旧选择和迟到结果，并减少低价值请求。

项目启示：可以借鉴候选结构、用途区分与按需要调用。足球案例共享公开球场状态，不足以证明可以把桌游不同角色的私人信息放在同一请求。它的自动切换策略也不能直接继承为本项目的角色决定。

### 2.4 StartLux 的星际争霸与 Doom：战略和底层执行分工

[官方演示说明](https://github.com/StartLuxLabs/StartLux-Decision/blob/main/v1/README.md)说明：星际争霸按较低频率选择建设、单位和战略，脚本完成生产与控制；Doom 的移动、瞄准等环节也由程序承担，游戏等待模型决定。

项目启示：演示不能归结为模型独自玩完整游戏。桌游可以把计算和规则交给专用代码，同时让模型在实际有区别的行动中表达角色选择。

### 2.5 NPC 说话对象识别：只证明其中一个窄任务

[公开数据及问题构造](https://github.com/wondertwins/jev-benchmark/tree/main/npcaddress)处理玩家是在对谁说话，区分称呼、谈论、转述和自言自语。它没有验证完整的人格、台词、情绪更新和桌游共玩系统。

项目启示：语义路由具有参考价值，但不能把“识别被说话对象”直接当作“知道谁最想接话”或“能稳定扮演某个人”。

米哈游的相关桌游设想可以作为产品体验参照。本次没有取得可核对其调用、训练、延迟与成本的一手实现资料，不使用转载描述推断其内部架构。

## 3. 协议与模型局限

### 3.1 短输出仍然需要读取输入

[TypeSafe 状态说明](https://docs.typesafe.ai/concepts/state)规定同一请求的各问题独立读取同一份状态，并提示非英语任务存在效果差异。共享请求不会隔离每个问题看到的私人材料；问题之间也没有先后依赖。

[Jev 1.13 官方限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)列出数值精度、间接推断、无关长状态和候选顺序等问题。它描述具体版本，不能当作所有后续模型的永久结论；这些风险仍应进入本项目测试。

### 3.2 置信度和棋局质量分别处理

[TypeSafe 置信度定义](https://docs.typesafe.ai/confidence)中，Choice 的 `confidence` 由返回分布计算，不是独立的正确性证明。几个候选同样合适时，分布可以较平；缺少好候选时，也可能对坏选项很自信。

因此，升级到生成模型的依据应包括候选覆盖、目标冲突和任务需要。不能简单规定“概率低于某个值就调用大模型”，也不能把候选概率当作胜率或情绪数值。

### 3.3 一次 HTTP 请求不等于一次前向计算

[StartLux 接口文档](https://github.com/StartLuxLabs/StartLux-Decision/blob/main/docs/api.md)说明：较大选项列表会分组选择；Instant 与 AutoThink 的输入复用及推理行为不同。AutoThink 的困难请求会生成推理文本，失去单次前向的时间特征。

项目应固定并记录具体模型与执行参数；高频用途采用不生成推理文本的路径。统计实际输入、问题数、服务器内部处理和端到端时间，不能只数客户端请求。

### 3.4 单步更快不能保证整局更好

[JEVal 研究预印本](https://arxiv.org/html/2610.03935v1)报告长上下文退化、概率过度集中，以及多步工作流中较快选择与较低整体成功率并存。其工作流表格和部分正文数值不完全一致，本文不采用具体成功率作项目预测；它提供的是需要独立验证的风险证据。

项目应评价完整对局、连续承诺和失败恢复。不能只展示某次判断速度或某盘胜利。

## 4. 本地五子棋分析器

[Rapfi 官方仓库](https://github.com/dhbloo/rapfi)提供自由五子棋／连珠分析、搜索、权重和进程通信协议，可作为局势分析依赖研究，不需要本项目自写完整棋力引擎。它提供建议，正式游戏服务仍负责合法性和权威状态。

引入时需要核对自由规则、坐标、执子方、候选读取、计算预算和进程关闭。引擎原始分值不直接等于玩家胜率。

分发条件以[Rapfi 官方许可](https://github.com/dhbloo/rapfi/blob/master/Copying.txt)及实际使用权重的说明为准；[StartLux 仓库](https://github.com/StartLuxLabs/StartLux-Decision)也分别说明代码与权重许可。本文不依据开源标签推断商业分发条件。本轮没有安装或运行这些模型、引擎。

## 5. 能支持的项目决定

| 设计决定 | 支持它的依据 | 仍需项目验证的内容 |
|---|---|---|
| 本地计算候选及后果 | 象棋、马里奥、足球均有明确分工 | 五子棋候选是否保留好棋和角色表达空间 |
| 决策模型直接选择动作 | 多个公开案例展示固定动作选择 | 中文角色、聊天干预及实际棋力 |
| 文本模型按表达和复杂理解调用 | 决策协议不负责开放台词；复杂任务有能力差距 | 触发是否恰当、升级是否过多、人格是否连续 |
| 短输入与少量候选 | 官方限制与实际请求构造 | 输入删减是否遗漏重要承诺或隐藏限制 |
| 整局成本与质量联合评价 | 模拟成本、多步错误累积、迟到处理 | 真实模型费用、CPU 开销、P50／P95 延迟和完整对局 |

这些材料支持实施一个有分工的系统，尚不足以承诺固定降本比例或固定棋力。
