# 事实记录与角色认知：记忆方案调研

调研日期：2026-10-13。状态：暂存讨论稿，未修改业务实现或正式设计。

## 1. 结论与推荐基准

**需要把角色获得的信息，与角色对信息形成的认识分开。上一轮把事实、感受和推断统一定义为“长期记忆项”，没有明确它们不同的生成、更新和使用规则，仍然存在职责混合。**

本次找到直接相关的公开实现：Generative Agents（生成式角色智能体）区分观察与反思，并保存反思的证据指向；Concordia（社会模拟框架）区分观察输入与组件生成的认识，读取观察时过滤其他产物。这比继续讨论页的大小和名字更接近当前问题。

我推荐以 **Generative Agents 的观察／反思分离架构**为主要参考，采用有类型、有来源的记录，借鉴 Concordia 对观察与派生产物的读取隔离。事实条目的归并、认识的更新及有限检索使用现有工程中已有的明确集合与更新模式。

推荐的基础结构是：

- 原始来源和经历段保存可核查材料；摘要提供阅读便利。
- 事实记录保存角色实际获得的信息，区分观察、别人陈述和自身当时的内心记录。
- 认知记录保存角色由材料形成的理解、判断和印象，明确依据及形成时间。
- 核心记忆和关系描述根据这些记录准备上下文，不成为新的外部事实来源。

这是一套依据已发表架构和公开代码提出的本项目应用建议。公开方案尚未提供一个可以直接安装、自动保证“客观事实与角色认知永不混淆”的完整标准系统。能够复用的是已经实现的分离方式、证据引用和读取规则；本项目仍须明确哪些来源有权证明什么。

当前不推荐以泛实体图、模型自报概率、多层递归认识或主动遗忘作为基础。它们应在固定基础方案上单独实验，避免同时改变多项机制后无法解释结果。

## 2. 首先明确：事实记录能确认什么

### 2.1 世界事实、可见信息和推断有不同含义

| 内容 | 可以确认的范围 | 不能自动确认的内容 |
|---|---|---|
| 正式活动模块提交“甲把棋子移到 A3” | 这项业务动作实际发生，角色只能读取自己可见的部分 | 所有角色都已经知道；甲这样做的隐藏动机 |
| 小明说“我喜欢蛋糕” | 小明在该时间说过这句话，当前角色听到了 | 喜好绝不会变化；小明没有撒谎；所有蛋糕都喜欢 |
| 角色 Thought 记录“我有点害怕” | 系统保存了角色当时的内心记录，可以作为角色自己的体验依据 | 外部对象一定危险；其他角色知道这份内心 |
| 角色由一次冲突认为“这个人可能不尊重我” | 角色形成了这项判断及其依据 | 对方的真实动机；这项判断已经被证明正确 |

“小明说他喜欢蛋糕”可以忠实地成为陈述记录；“小明喜欢蛋糕”若作为角色认识使用，应保留来自小明自述的性质。不能只靠模型给出的 `confidence=0.9` 把自述升级为独立验证的世界事实。

普通聊天中的行动描述也遵守这个原则：一条“我打了你”的消息，首先证明发送者说了这句话。它是否同时代表正式世界中的动作，应由该场景所属业务入口决定。记忆整理不能越过活动规则确认动作成功。

### 2.2 情绪也需要判断来源

“我开始害怕见这位甲方”可能有两种来源：

1. 当时的内心或状态已经明确记录害怕。这是角色当时的体验记录。
2. 反思根据冲突推断以后可能不愿见面。这是新生成的认知，需要引用依据，不能补写成当时已有的情绪。

只按句子里是否出现“我觉得”“害怕”分类会误判。分类要看内容怎样获得、描述哪个时刻、是否增加原材料没有的结论。

### 2.3 两类长期产物与来源性质可以共同存在

用户提出的“事实与认知分开”是长期产物的职责划分。事实记录内部仍然需要保留来源性质：直接观察、他人陈述、自身记录等。它们都能成为认知依据，但能证明的范围不同。

这无需增加一个新的业务系统。现有原始消息、内心、状态、作者材料和活动结果仍由各自模块负责；记忆模块保存角色可知的记录和认识，反思负责提出候选。

## 3. 已有方案的实现与成熟程度

“有成熟实现”在本报告中表示可以核查的公开代码或正式产品接口。研究中的效果证明、长期运行的工程能力和适合本项目的业务语义分别评价。

### 3.1 Generative Agents：最直接的角色记忆参考

2023 年论文把观察和 reflection（反思所得认识）作为不同记忆。反思读取经历，生成认识并引用支持记录；检索考虑相关性、时间和重要程度。作者代码分别维护事件、聊天和思考记录，反思保存所引用记录的编号。论文有角色行为可信度实验，也报告检索遗漏与细节编造。[论文](https://arxiv.org/html/2304.03442v2)、[记忆结构](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/memory_structures/associative_memory.py)、[反思实现](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/cognitive_modules/reflect.py)。

**可以采用：** 观察和认识分别标识；认识指向依据；按当前需求读取两类内容。

**需要明确边界：** 观察是角色获得的材料，无法保证所有陈述客观正确；其实现允许对旧反思继续反思，证据引用也不能自动证明推断正确。本项目不需要照搬固定数量的高层洞见或递归反思树。

### 3.2 Concordia：观察与认识的读取边界已有代码

Concordia 用环境编排者管理模拟事件，角色根据收到的观察行动。当前公开代码把观察写入带 `OBSERVATION_TAG` 的记忆；观察读取组件过滤没有该标记的记录。其他组件能够根据近期记忆回答自我认识和情境问题，并可以单独选择是否保存及保存标签。[论文](https://arxiv.org/abs/2312.03664)、[观察组件](https://github.com/google-deepmind/concordia/blob/main/concordia/components/agent/observation.py)、[认识组件](https://github.com/google-deepmind/concordia/blob/main/concordia/components/agent/question_of_recent_memories.py)。

**可以采用：** 环境事件与角色理解分工；观察读取不混入派生认识；并非每次临时判断都必须保存为长期记忆。

**需要明确边界：** 文本标签不会自动完成真假验证，也不能保证每项认识都有细粒度依据。部分组件默认不保存认识。它是架构参考，不能据此声称角色认知的完整维护已经解决。

### 3.3 LangMem：可用的记录集合与更新工具

LangMem（长期记忆开发工具）支持 semantic memory（知识与事实）、episodic memory（经历）和 procedural memory（行为规则）。知识可以存为多个记录或按对象维护资料，接收旧记录并进行插入、修改和删除。开发者可提供结构化类型。官方示例也把根据说话风格推断的性格写进知识集合。[概念与示例](https://langchain-ai.github.io/langmem/concepts/conceptual_guide/)、[集合提取接口](https://langchain-ai.github.io/langmem/guides/extract_semantic_memories/)。

**可以采用：** 明确的记录类型、有限旧记录检索、重复信息处理与更新操作。

**需要明确边界：** “语义记忆”不等于已经验证的客观事实。默认集合可以混入推断，因此仅套用它的类型名称不会解决本项目问题。它的经历学习与提示优化示例主要面向完成任务，不能直接规定角色性格如何演化。

### 3.4 Letta：上下文位置划分较清楚，真实性需要应用负责

Letta（有持久记忆的智能体框架）提供始终在上下文中的 memory blocks（记忆块），以及按需搜索的 archival memory（归档记忆）。记忆块可以按人物、自述、对象等用途组织，并通过明确工具更新。[记忆块](https://docs.letta.com/v1-sdk/memory/memory-blocks)、[归档记忆](https://docs.letta.com/v1-sdk/memory/archival-memory)。

**可以采用：** 常驻内容与按需检索内容分工。

**需要明确边界：** 这是材料放在哪里、怎样读取的设计，不构成客观事实与推断的自动分离。将两个自由文本块命名为“事实”和“认知”，仍须提供来源和生成规则。

### 3.5 Mem0：事实整理产品可用，但“提取事实”不等于验证事实

Mem0（记忆存储与检索工具）的正式文档描述了模型提取、相关记录查询、语义和关键词检索；也允许关闭提取以原样保存输入。文档区分托管产品与开源实现的能力，当前页面说明自动提取路径可追加新信息，明确更新和删除另有操作。[当前工作方式](https://docs.mem0.ai/core-concepts/how-it-works)、[官方文档源码](https://github.com/mem0ai/mem0/blob/main/docs/core-concepts/how-it-works.mdx)。

**可以采用：** 原始输入与整理结果分开，按产品实际需要更新。

**需要明确边界：** 提取开关控制处理过程，无法表示一句话的认识性质。“用户喜欢蛋糕”仍可能只是自述；通用记忆产品不负责角色视角和世界权威状态。

### 3.6 CoALA：记忆类别与认识性质属于不同维度

CoALA（语言智能体认知架构）整理经历、语义知识、程序知识与工作记忆，并讨论从经历推理后写入语义记忆的学习过程。因此，语义记忆可以包含推理所得认识，不能简单对应客观事实。[论文](https://arxiv.org/html/2309.02427v3)。

**本项目判断：** fact、event、preference、promise 等说明记录谈什么；观察、陈述、推断说明信息怎样获得。只调整主题类别，仍然无法阻止推断变成事实。

### 3.7 BeliefMem：很相关，仍应作为实验方法

2026 年 BeliefMem（部分可观察环境中的信念记忆）保留同一次观察的多个可能结论及概率，使用新证据更新，并在检索时呈现候选。作者在 LoCoMo 和 ALFWorld 上报告实验结果。[论文](https://arxiv.org/html/2605.05583v2)。

**可以借鉴的判断：** 模糊证据不应被压成唯一确定结论。

**当前不作为基础：** 论文的候选概率及更新算法属于具体研究机制；本次没有独立复现实验，也没有找到它在本项目这种角色社会互动中的可靠性验证。模型概率的准确性、重复来源的相关性和长期维护成本都需要单独检验。

### 3.8 角色错误认知与反思风险已有研究

2015 年 Talk of the Town（小镇叙事角色项目）研究角色观察、转述、遗忘、错误记忆和说谎，表明世界与角色知识可以分别建模；该论文介绍的是研究框架与当时开发中的体验。[论文出版页](https://ojs.aaai.org/index.php/AIIDE/article/view/12825)。

2026 年 Honest Lying（反思记忆编造研究）在特定 Reflexion 任务日志中发现错误解释被持续保存并影响后续尝试，也明确其测试范围与检测限制。[论文](https://arxiv.org/html/2605.29463v1)。

**本项目判断：** 角色可以有来源支持的误解；系统不能把整理错误当成角色个性。将一次推断反复读取和重写，也不能作为新的独立证据。当前无需主动模拟遗忘、说谎或错误记忆。

## 4. “成熟方案”具体应采用什么

建议采用一套清楚的观察／反思分离方案，而非把不同研究系统的全部机制组合起来。

| 基础能力 | 参考依据 | 本项目中的职责 |
|---|---|---|
| 观察与反思分别标识 | Generative Agents、Concordia | 事实记录与认知记录有不同类型及生成规则 |
| 认识引用支持材料 | Generative Agents | 认识能够回查实际可见来源 |
| 明确集合与更新操作 | LangMem | 查找同一事项、避免重复、补充依据与修正认识 |
| 相关性优先的有限检索 | Generative Agents 及通用记忆工具 | 返回回答当前问题所需的记录，保留类型与时间 |
| 常驻与按需读取分别安排 | Letta 等框架 | 核心上下文少量常驻，其他内容按需要读取 |

“按成熟方案实现”的重点应放在这些可核查能力上。外部框架的完整社会模拟、代理工具循环和存储服务，与当前 Runtime、Domain、Store 及 SQLite 有不同边界；采用其架构模式无需整体移植其运行系统。

这套基础方案保持角色能够从经历形成认识。它不要求角色只能复述记录，也不要求每个推断都与世界真实情况一致；要求的是推断身份、依据和更新过程保持清楚。

## 5. 当前代码已有能力与真正缺口

### 5.1 已有能力可以继续使用

- 原始消息、自身 Thought（内心记录）、作者材料、关系证据和状态有独立来源。
- 消息受众、成员区间和角色视角决定可读范围。
- 反思材料协议区分消息、内心、摘要和正式记录。
- 长期页已有逐项来源及版本。
- 关系描述、自身状态摘要与核心记忆属于已有认识刷新流程。
- 模型候选通过正式运行入口审核与保存，模型不能直接修改数据库。

这些机制不需要为本次调研新建业务模块。

### 5.2 混合发生在哪里

| 环节 | 当前行为 | 缺口 |
|---|---|---|
| 段摘要 | 消息和自身 Thought 一起读取，输出一份第一人称正文 | 来源类型进入输入，但正文没有可读取的分类结构 |
| 连续摘要 | 归并事件、约定、感受与猜测 | 依赖模型在文字中保持性质，后续无法按性质筛选 |
| 长期页 | 一件事或主题，允许事实、感受和判断共同叙述 | 单个类型表示主题，无法说明哪些句子是推断 |
| 核心记忆 | 从有效页面生成常驻经历与认识 | 页面混合时，引用页面不能证明每句认识的依据类别 |
| 关系描述 | 已有独立对象与证据 | 支持部分角色认知，但不覆盖对事件、计划和世界的其他认识 |
| 正式状态／关系数值 | 模型候选经规则提交后成为正式记录 | 数据已获准不表示其中的心理解释成为外部客观真相 |

当前提示其实已经要求区分说法、感受和事实，问题不能归结为完全没有规则。缺的是保存与读取层能持续保留区别的协议，以及相应验收。

## 6. 适合角色记忆的应用方向

以下是依据上述已有方案提出的设计方向，尚未形成代码实施计划。

### 6.1 原始记录和段摘要

原始来源保留各自性质。段维护经历范围与顺序，摘要作为快速阅读材料。摘要可以同时概括外部交流与当时内心，但两部分需要明确分类；不能把混合摘要当作已确认外部事实清单。

如果采用“段摘要只记录外部交流”的定义，自身当时内心仍须保留在单独可读材料中。不能为了事实清晰删除角色当时的体验。第一人称和第三人称只是写作形式，不决定记录是否客观。

长期提取必须能够读取对应原始来源以确认依据性质。摘要可以辅助寻找内容，不能仅引用另一份摘要就把其中推断升级为观察事实。

### 6.2 事实记录

事实记录围绕一项明确的信息，不生成新的动机、性格或因果。

必要信息包括角色归属、相关对象、来源性质、内容、发生或表达时间、获知时间及来源引用。日期未知时保持未知，不能把整理时间填作事件时间。

例如：“10 月 10 日，小明向我说他喜欢草莓蛋糕。”其他时间他说不爱吃甜食，两条陈述都可以保留。是否改变了偏好、针对什么场合，需要材料说明。

同一来源被摘要、长期提取和核心整理多次，不应算成多份独立证据。

### 6.3 角色认知

认知记录表达角色目前怎样理解一个对象、事件或自己。它需要明确引用支持的事实记录或原始材料，保留形成时间和适用范围。没有新认识时允许不生成。

认知可以受到人物背景和表达习惯影响，但人物背景不能补写外部事件。角色可以有限地怀疑、误解或逐渐改变看法；因整理丢失了来源而制造确定结论不属于有依据的角色认知。

对于“甲方打我”的例子：

| 部分 | 可以保存的内容 |
|---|---|
| 来源支持的行为 | 那次冲突发生了什么，以及角色怎样得知 |
| 明确陈述的原因 | 甲方说是因为延期交稿；保留是谁作出的说明 |
| 当时内心 | 角色当时记录自己害怕或愤怒 |
| 后来认识 | 对这位甲方的有限不安或不信任，引用上述依据 |

若原因只有角色推测，应保存为推测；不能把“因为我消极怠工”固定成未经证实的自我归因。一次冲突也不应自动写成永久的处世规则。

### 6.4 更新和纠正

事实记录保留原始来源，出现新材料时补充或新增。模型提取错误可以通过正式入口修正，同时保留可追溯依据。

认知读取新材料与旧认识，决定维持、细化、减弱或修正。较新的说法不自动等于正确说法，未涉及同一条件的差异也不自动视为矛盾。

来自另一角色的秘密或管理端知道的事实，不参与当前角色的认识更新。只有当前角色实际获知的材料才能影响其认知。

### 6.5 检索与上下文使用

问题决定读取类型：

- “他当时说了什么”“那件事怎么发生的”：优先事实记录及经历来源。
- “你现在怎么看他”：读取对应认识及必要依据。
- “这个约定完成了吗”：读取具体约定和实际完成记录，不能只凭角色印象作答。

上下文需要保留内容类型和时间。面向用户的角色语言无需暴露内部标签；它可以自然地表达“他告诉过我”“我当时以为”“后来我才知道”。

事实与认知仍共用相关性和输入预算控制。拆分类型不能成为每次把两套材料全部发送的理由。

### 6.6 与已有模块和图删除的关系

事实记录及长期认知的持久化、查询和来源由 memory（记忆模块）负责；候选生成、审核、调度和恢复由 reflection（反思模块）负责。关系态度与状态仍由现有所属模块维护，避免增加一套同义状态。

删除当前实体图不能删除逐项来源、正式人物身份和可见性。事实记录到认知的依据引用必须保留；普通外键和来源引用即可表达这种依赖，无需运行泛实体图检索。

未来若实验记忆项之间的逻辑联系，必须区分证据依赖、事件后续与因果假说。不能把三种联系都标成“相关”或“因为”。

## 7. 应通过实验决定的角色特化

| 特化机制 | 需要回答的问题 |
|---|---|
| 人物性格怎样影响推断 | 是否产生符合角色但有依据的不同理解，而非增加编造 |
| 多个可能解释及概率 | 是否改善不确定情景；概率是否可靠；输入与维护开销是否值得 |
| 旧认识的逐渐变化 | 是否比当前认识替换更自然，同时不反复保留过时结论 |
| 主动遗忘与错误记忆 | 是否有明确玩法价值；必须与系统丢失和整理错误区分 |
| 反思继续反思 | 是否提供额外洞见，还是重复放大最初推断 |
| 跨项逻辑联系 | 是否找到普通检索遗漏的必要依据，且没有无关扩展 |

基础比较固定角色、原始经历、检索能力、模型和上下文预算。特化每次只改变对应机制，保留生成输入、记录及实际回答，避免把更强模型或更多材料的收益归因于特化。

## 8. 基础方案的验收要求

| 情景 | 正确行为 |
|---|---|
| 小明自述喜欢蛋糕 | 保留自述来源，不编造亲眼见过他吃蛋糕 |
| 用户声称某个动作已完成 | 按业务入口区分陈述与正式结果 |
| 内心记录怀疑对方撒谎 | 认识仍为怀疑，不写成对方确实撒谎 |
| 原始材料没有害怕情绪 | 不把后来推断改写成当时已有的情绪 |
| 新证据改变旧判断 | 更新角色认识，仍能解释当时为何这样理解 |
| 两名角色获得的信息不同 | 分别维护认识，不能通过公共图或后台事实自动共享 |
| 已有认识被再次总结 | 不增加独立证据数量，也不自动增强确定程度 |
| 查询具体经过 | 不以人格评价替代发生记录 |
| 查询当前态度 | 可以表达认识，不要求逐条复述全部事实 |

验证需要检查存储类型、来源、更新和上下文，再检查回答。正文自然、模型给出高置信度或引用合法编号，均不能单独证明实现正确。
