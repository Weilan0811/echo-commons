# 日志、追踪与诊断

## 1. 三类信息

| 记录 | 内容 | 使用目的 |
|---|---|---|
| 普通日志 | 事件、范围、错误码、请求次数、耗时和真实用量 | 定位执行阶段 |
| trace_outbox / traces | 关联身份、来源、时间、有限事件载荷、投递状态 | 查看业务执行来源链 |
| AgentDebugCapture | 显式开启后的完整模型输入输出和工具材料 | 检查具体生成过程 |

消息、任务、节点产物和记忆表保存事实。诊断能定位事实，不能代替事实。普通日志只允许有限元数据，不记录密钥、玩家正文、Thought、完整提示和工具正文。

## 2. 事务外投递

业务事务写 trace_outbox；独立 TraceWorker 用租约领取，TraceDelivery 将事件按 trace_id 去重写入 traces 并完成 outbox。投递失败保存真实原因和下次时间，有限重试，不撤销业务结果。默认尝试 5 次、退避 1 秒、租约 30 秒、批量 25，见 [配置](../reference/configuration.md)。

读取接口同时显示已投递与待投递事件，按真实身份和状态呈现。同一回应的请求、轮次、任务、Invocation、审核和提交通过关联标识连接；反思关联图、节点、Artifact 和事实。

## 3. 内部读取与隐私

对话诊断验证社群、角色及任务归属，返回实际冻结上下文；图诊断验证社群角色，返回运行、节点、产物、审核及来源。已清除 Thought 不得在后续诊断重新返回。完整捕获的保留目录是独立文件存储，清除数据库原文不会自动删除过去显式生成的捕获文件。

公开消息和轮次用独立响应类型过滤私有数据。内部路径用于本地开发诊断，当前没有账户认证；玩家功能使用正式公开接口。对外部署所需的访问控制属于后续明确部署设计。

## 4. 健康与退出

/health/live 判断服务存活；/health/ready 检查数据库结构和真实后台工作状态，不发送额外模型请求。Workers 关闭时的工作状态必须明确，不能把模型供应商超时转换成人物状态。

例如发言提交成功后追踪投递遇到暂时错误：玩家仍能读取发言，内部查询看到 outbox 的等待状态；后续投递完成，模型无需重新生成。

配置、路径、轮转和开关见 [配置参考](../reference/configuration.md)，逐阶段排查见 [故障指南](../guides/debugging-and-recovery.md)。
