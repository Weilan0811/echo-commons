# diary_compose：按游戏日整理私人经历

状态：暂缓的保留设计，不属于 Demo 的四种反思图。当前 Thought 随角色输出记录保存，不安排自动清理；下文的日记覆盖与清理方案仅保留为未来设计，不能作为当前任务依赖。

## 1. 设计目的与触发

日记把一个角色在某个游戏日的真实经历整理成第一人称回顾，作为角色私有记忆保存。日记生成只写入自己的正文和来源覆盖。

运行范围为社群、角色和 game_day。游戏日由世界时间及社群时区计算，不能用工作进程的日期代替。目标触发包括游戏日结束及明确的世界时间结算；自动调度策略和操作入口尚未接入，当前不能宣称每天自动写日记。

没有真实当日材料时，不创建日记或空白图。已有日记的补充应当成为明确的材料版本处理，不能用重复定时触发覆盖历史。

## 2. 材料与冻结输入

材料来自当日的自身 Thought、已审核段摘要及明确允许的经历记录。每项包含正式身份、版本、时间与覆盖。跨午夜的段必须按真实来源确定当日材料，不能把整个段仅按生成时间归到新的一天。角色没有看到的消息不进入日记。

diary_context.v1 应提供游戏日边界、身份、自身状态及关系认识、允许记忆、当日材料和已有覆盖。统一材料数量、字符和模型调用预算适用；材料超限时需要明确的摘要或选择策略，不能静默省略后又宣称完整覆盖。具体长期日记材料策略尚待接入时确定。

## 3. 两节点拓扑与行动

```mermaid
flowchart LR
  D[当日精确材料及游戏日范围] --> M[diary_compose<br/>模型]
  M --> A[diary_aggregate<br/>代码]
  A --> R[审核、日记与覆盖事务]
```

| 节点 | 输入 | 输出 |
|---|---|---|
| diary_compose | diary_context.v1，真实材料、身份及已知个人认识 | DiaryAction：game_day、content、evidence_refs；允许条件明确的 NoOp |
| diary_aggregate | reflection_artifacts.v1，模型产物及实际来源 | DiaryAppendCandidate 或正式 NoOp |

正文非空且最多 6000 字符。game_day 必须等于输入游戏日，不能让模型调整日期。正式日记标识、实例、来源版本、记录时间和覆盖由运行层提供。内容可描述角色感受，不能补造没有来源的同行、承诺或活动结果。

日记正文使用共同反思的第一人称规则，保持角色当时的认识和不确定程度。材料只证明对方说过某件事时，日记保留陈述归属；角色曾经猜想某种结果时，不能改写成结果已经发生。已保存的活动结果接入后，也只允许使用本角色真正观察到的部分。共同表达规则与固定正文见 [反思提示契约](../character-prompt-contracts.md#5-共同反思输出规则)。本图专属模型提示保持未实现。

## 4. 审核、唯一性与 Thought 清理

审核检查日期、角色、可见来源、来源版本、正文预算及覆盖准确。`(community_id, character_id, game_day)` 为业务唯一范围；一致的重复返回已有结果，不一致内容必须通过明确补充或冲突处理，不能默默覆盖。

日记、材料覆盖、结果和来源状态同一事务提交。NoOp 不创建空日记；有材料却不产出的许可理由和覆盖处理必须由正式策略决定，不能直接复用连续性或记忆整理的消费规则。

Thought 原文只有满足既定保留及覆盖策略、且没有未完成图依赖时才可清除。清除更新原记录，保留身份、版本及来源关系；日记覆盖不能代替其他仍需要原文的消费者。模型节点失败不写入日记、不清除 Thought。

## 5. 运行例子与实现边界

甲上午参加群聊，留下自己的 Thought；晚上独自与 Alice 交流。乙只参加上午群聊。游戏日结束时，甲的候选日记可以提到两段经历及自己的感受，乙的日记只能使用上午的自身材料。没有参与任何事件的丙不产生“平静度过一天”之类虚构日记。

保留历史图种类、两节点定义、行动契约和日记存储，不在运行注册中提供本图。正式日期材料读取器、触发器、输入准备、图审核特有规则、日记消费者和清理协调均暂缓；Thought 不依赖日记保存或清理。
