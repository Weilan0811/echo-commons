# 角色观察与任务上下文

## 1. 三种信息的含义

共同上下文的 `PerspectiveContext.participants` 保存本次可见参与者的稳定人物身份、显示名称和本人标记。聊天发送者、回复对象和提及保留同样的身份对应，同名人物分别展示。活动输入额外组合参与编号与席位，具体层级见[活动任务状态](activity-context.md#任务状态与身份)。

perspective 表达角色实际能观察到的消息、公开主体、会话、时间及权威活动结果。消息正文仍保留说话者及陈述性质。characters 保存短时状态、关系数值及态度表达；memory 保存自身 Thought、摘要、长期事实和认知，原始发言由 conversations 保存。长期信息和角色理解的区别见 [记忆定义](memory.md#1-原始记录摘要和长期记忆)。

任务输入把这些材料分组组合，存储模块仍按实际事实归属划分。身体自述可以是主观状态；游戏权威位置或其他规则状态由独立游戏模块决定，不能被自述覆盖。

## 2. 观察范围与可见性

ObservationScope 指定社群、会话、观察主体、消息上限和需要时的原成员区间。消息可见必须同时满足：同社群、同会话；序号不超过上限；实际成员区间覆盖该消息；区间存在于消息受众。

离开保留原经历，重新加入产生新区间。历史范围包含旧私有消息或成员离开期间的序号缺口时仍逐条验证。公开身份读取不得返回其他角色内部关系、状态或记忆。

跨会话经历按实际发生时间排列；时间相同时，按会话编号、会话消息序号和消息编号稳定排列，保持同一会话中消息的先后顺序。

MessageQuery、上下文准备、检索返回、索引重建、归段和反思来源复用相同资格。索引只给出候选，正式来源集合及版本决定结果。不可见内容也不能改变该角色允许来源的版本。

## 3. 快照内容与来源

| 字段组 | 必须表达的内容 |
|---|---|
| scope | 社群、角色、会话、原区间、轮次及冻结观察上限 |
| self | 模板绑定、实例名字、共同规则、档案、语气、关系倾向、状态、相关关系与能力 |
| perspective | 当前完整来源输入、根玩家输入与触发消息编号、预算内历史、带发送者及提及和回复关系的消息、公开主体 |
| memory | 有限常驻视图和预置材料、连续摘要、尚未覆盖的近期段摘要、按类型提供的长期事实与认知、自身历史思考来源 |
| environment | 世界 UTC 时间、社群时区、世界观、社群规则、社群版本、社群状态和会话类型 |
| action_space | 本次允许的输出契约及只读工具 |
| source_versions | 所有实际材料的类型、身份与版本 |

聊天与反思快照使用 schema_version=2，另保存 snapshot_id 和 prepared_at_utc。聊天 scope 的 conversations 和反思顶层 conversations 保存完整冻结场景。规划时在同一一致边界组装并持久化，后续执行与重试读取原输入。输入、类型引用和调用身份必须一致。

社群设定修改后，新任务读取新正文和版本，已冻结任务保留原内容。旧快照省略的新增环境字段在再次序列化时继续省略，时区按UTC解释。提示按社群时区展示时间，区分消息发送时间与消息中提及的事件时间。

## 4. 历史裁剪与自身思考

聊天以当前会话为回应位置，其他群聊与私聊按场景提供背景。新聊天输入先保留人设、当前来源及直接回复对象，再按剩余容量的 60%／30%／10% 组织当前场景、临近经历及较早相关记忆。空余容量按这个顺序继续分配；最近 20 条、6000 字符继续用于旧冻结输入及尚未更新的活动准备，新聊天按实际容量选择。

临近场景轮流取得材料名额，场景排序同时考虑近期程度、查询相关性，以及自身发言、被提及、回复或已经整理的片段。近期程度按 `1 / (1 + 间隔秒数 / 3600)` 计算，相关性使用共同分词的查询词覆盖比例，结构性重要材料加 0.25。选择由程序完成，不增加模型筛选调用。该排序决定提供哪些背景，角色仍根据真实材料判断其意义。

每个场景先提供最近片段，再按上述分数补充相关原话和摘要。较早但直接涉及当前问题的内容可以进入预算，消息密集的场景同时保留最新近况。

当前会话按顺序提供：自身消息使用 assistant，其他发言使用 user。外部场景全部作为带场景标题的 system 背景，自己的外部发言也保留为历史观察。提示逐条保留简短时间、自然发送者、正文；回复用原文短引用，存在提及时附上对象称呼，历史指定受众消息附上私人范围。同名人物保留原名，自身发言、提及及引用称呼标为“（你）”。提及名称随消息冻结，尚未发言和简单模式均可读取。当前会话实际展示消息从 1 编号，其他场景背景使用history来源标识，不能作为回复编号；回复转换规则见 [角色提示契约](character-prompt-contracts.md#2-对话输出规则)。完整身份、受众、来源、序号及触发记录留在快照；模型输入按交流经过组织。

自身 Thought 按已批准结果与自身发言关联，只有观察角色可以读取，正文已清除时省略。发言及 Thought 同时保留或裁剪；根玩家输入、当前触发输入及直接回复所需原文必须保留。最终输入同时检查完整请求字符数和模型上下文容量，包含工具定义、输出字段说明及附加的表达要求，预留实际输出额度。无法容纳必要输入时报告 `context_budget_exceeded`，保留原始来源。

连续性资格以精确来源判断：当前会话摘要的来源早于本次触发输入，其他场景受各自冻结上限和观察时刻约束。新聊天读取有资格的摘要候选并按共同容量选择，已覆盖原文保留每场景默认四条重叠。当前场景原文需要退出持续携带范围时，先通过既有反思任务完成摘要；成功覆盖前保留原文，聊天不领取执行租约。来源读取截止先固定，等待期间的新消息留给后续任务。

`memory.input_budget` 保存模型条目、容量、计量方式、输出预留和工具说明；`memory` 另保存分配比例。`context_prepared` 表示材料准备是否完成，`summary_message_ids` 标识等待整理的来源。准备结果和成功覆盖保存在现有任务及记忆记录中，重启继续原范围。新摘要可以在读取截止之后生成，其全部原始来源仍须属于冻结范围。完整输入完成后只保存实际使用的材料版本。旧快照缺少这些字段时保留原序列化及恢复方式。

旧材料选择分支服务于缺少共同预算字段的历史冻结任务；新活动判断与普通对话共用材料选择和摘要等待。历史执行用途结束后清理旧选择逻辑。历史快照的来源与管理读取继续保留。

段与连续摘要可以在单份正文中交代经历和当时理解，私人交流仍保持原来的知情范围。长期事实和认知分别标明性质、必要时间和依据场景；它们与常驻视图仍属于角色个人经历。当前有效性与支持读取见 [记忆](memory.md#6-搜索与重建) 和 [认识刷新](reflection/view-refresh.md)。

近期原文由 memory 在既有容量选择前确定必要保留范围：当前窗口最后两条消息、最近一次自身发言及紧邻的前后交流、这次输入和最近自身发言直接回复的可见对象。`protected_message_ids` 保存实际可见的消息身份，消息及其自身 Thought 一起计量。摘要已覆盖这些消息时仍保留原文；其他历史继续使用既有摘要和分配比例。必要原文超出总容量时报告明确失败。

保留范围先经过原会话、成员区间、受众和时间资格检查。它不扩大其他场景的可见范围；最终当前窗口仍按消息序号组织，跨窗口背景仍按各自场景提供。等待摘要时保持已经读取的范围与必要原文，恢复不会重新编号已经进入模型调用的输入。

## 5. 只读工具政策

ToolReadPolicy 保存观察时刻和完整 `conversations` 边界列表，每项包含会话身份、类型、名称、上限及角色历史成员区间。memory_search、自动检索和普通重试使用同一列表，不能把后来新增的会话、成员区间或消息纳入旧任务。

模型只填写查询和允许的结果数量。返回前按共同观察规则验证资格和版本，发生变化时返回明确来源变化。内部 SearchHit 保留正文、正式来源和 `context_label`（场景及私人范围），模型工具通过 `context` 字段读取。具体协议见 [提示契约](character-prompt-contracts.md#12-正式记忆工具的文字与协议)。

## 6. 各用途如何复用

ConversationTask 使用 ContextSnapshot，反思节点使用图快照及前驱产物的 ReflectionNodeInput。共同输入协议只表达身份、动作空间和来源等公共元数据，具体任务保留明确类型。目标 ActivityTask 使用真实可见棋局、规则与合法动作、局内消息和自身记忆，一次决策可以同时提出动作和发言。冻结输入保存紧凑游戏视图、游戏事件上限、消息上限及实际来源；详见[角色活动设计](activity-integration.md)。已有 `ActivityObservation` 仅为观察类型，接入时明确游戏身份与字段转换，不将其当作完整游戏存储。

共享阅读资格，各用途按需要选择材料。反思读取过去实际范围，不局限于当前活跃会话。活动的公开棋盘与私有手牌分别由真实玩法规则提供。

任务准备分三步：读取本角色的客观观察、自身状态和关系、私有记忆；保存带正式来源的完整快照；按具体用途选择字段并组织模型消息。完整快照便于重试和核查，各节点模型输入仍遵守 [反思投影矩阵](reflection/execution-model.md#2-节点输入与引用资格)。不能因为 self 与 memory 是共同数据组，就向每个模型节点发送全部字段。

例如消息 1 公共、2 仅甲可见、3 公共：甲快照可以含 1、2、3，乙含 1、3。两者世界上限均为 3，但材料与版本不同。甲先回应产生消息 4，新的接话安排为乙准备包含消息 4 的输入；乙任务开始后重试保持该输入。数据库迁移转换旧任务的冻结输入，原输入保留在审计中；正式执行只读取当前协议。根玩家输入属于必须保留的材料，不能被普通历史裁剪删除。具体安排见 [会话设计](conversation-and-social.md)。

边界验证覆盖私有查询、加入区间、重建、冻结来源、自身思考清除与多任务独立输入。关联设计见 [记忆](memory.md)、[Agent](agents-and-models.md) 与 [活动](activity-integration.md)。
