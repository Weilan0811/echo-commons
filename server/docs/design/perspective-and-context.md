# 角色观察与任务上下文

## 1. 三种信息的含义

perspective 表达角色能够观察到的客观世界：消息、公开主体、会话、时间及未来棋局和场景。角色的情绪、身体自述、意愿和有向关系认识表达自身主观信息，由 characters 保存。经历、长期记忆、摘要与自身 Thought 由 memory 保存。

任务输入把这些材料分组组合，存储模块仍按实际事实归属划分。身体自述可以是主观状态；活动权威伤势或位置由活动模块决定，不能被自述覆盖。

## 2. 观察范围与可见性

ObservationScope 指定社群、会话、观察主体、消息上限和需要时的原成员区间。消息可见必须同时满足：同社群、同会话；序号不超过上限；实际成员区间覆盖该消息；区间存在于消息受众。

离开保留原经历，重新加入产生新区间。历史范围包含私有序号缺口时仍逐条验证。公开身份读取不得返回其他角色内部关系、状态或记忆。

MessageQuery、上下文准备、检索返回、索引重建、归段和反思来源复用相同资格。索引只给出候选，正式来源集合及版本决定结果。不可见内容也不能改变该角色允许来源的版本。

## 3. 快照内容与来源

| 字段组 | 必须表达的内容 |
|---|---|
| scope | 社群、角色、会话、原区间、轮次及冻结观察上限 |
| self | 模板绑定、实例名字、共同规则、档案、语气、关系倾向、状态、相关关系与能力 |
| perspective | 当前完整来源输入、预算内历史、带明确发送者身份的消息、公开主体 |
| memory | 有限 resident、已有会话摘要、显式取回材料以及自身历史思考来源 |
| environment | 世界 UTC 时间、社群状态、会话类型和实际支持环境 |
| action_space | 本次允许的输出契约及只读工具 |
| source_versions | 所有实际材料的类型、身份与版本 |

快照另保存 snapshot_id、schema_version 和 prepared_at_utc。规划时在同一一致边界组装并持久化，后续执行与重试读取原输入。输入、类型引用和调用身份必须一致。

## 4. 历史裁剪与自身思考

当前输入和历史分开，历史按序保留。近期历史默认最多 20 条和 6000 字符，常驻记忆默认最多 32 条。已有 digest 时仅保留被覆盖历史的有限重叠，默认四条，避免重复装入全部已摘要材料。超预算材料留在正式存储，不能裁掉消息身份后变成无来源段落。

角色自己的历史消息投影为 assistant，其他玩家与角色消息为包含主体身份的观察输入。自身 Thought 按批准结果和对应历史发言关联，只有同一角色可读；没有 Thought 或正文已清除时不提供。目标规则将发言及对应 Thought 作为完整历史单元，共同计入 recent_message_max_chars，消息数量按发言计算；裁剪保留单元身份和顺序，不能保留不对应历史发言的游离 Thought。当前来源输入的自身思考同样必须明确用途，不能作为其他角色公开消息。

自身历史 Thought 与该角色对应发言一起进入历史输入，帮助角色保持自身认识和表达的连续性，其他角色无权读取。当前准备路径缺少该关联读取，修复计划见 [D01](../status.md)。意愿生成与分类保持未实现，当前空字段的处理见 [D06](../status.md)。

## 5. 只读工具政策

工具范围来自任务，而非模型参数。ToolReadPolicy 保存观察时间、当前会话和上限、来源版本。memory_search 只接受查询与正式允许数量；当前会话受冻结上限约束，其他实际经历会话仍受观察时间、成员与受众约束。

长期材料版本变化时返回明确来源变化，不混合新内容与旧快照。内部检索结果保留 source_kind、source_id、source_version、正文和会话信息，作为本次实际取回材料。发送给模型时通过明确转换生成工具契约规定的字段，完整字段和提示见 [记忆工具契约](character-prompt-contracts.md#12-正式记忆工具的文字与协议)。检索能力取消时模型定义和执行授权同时变化。

## 6. 各用途如何复用

ConversationTask 使用 ContextSnapshot，反思节点使用图快照及前驱产物的 ReflectionNodeInput。共同输入协议只表达身份、动作空间和来源等公共元数据，具体任务保留明确类型。未来 ActivityTask 使用实际棋局观察、状态版本与合法动作。

共享阅读资格，各用途按需要选择材料。反思读取过去实际范围，不局限于当前活跃会话。活动的公开棋盘与私有手牌分别由真实玩法规则提供。

任务准备分三步：读取本角色的客观观察、自身状态和关系、私有记忆；保存带正式来源的完整快照；按具体用途选择字段并组织模型消息。完整快照便于重试和核查，各节点模型输入仍遵守 [反思投影矩阵](reflection/execution-model.md#2-节点准备与提交)。不能因为 self 与 memory 是共同数据组，就向每个模型节点发送全部字段。

例如消息 1 公共、2 仅甲可见、3 公共：甲快照可以含 1、2、3，乙含 1、3。两者世界上限均为 3，但材料与版本不同。甲先回应产生消息 4，乙本轮重试仍不读 4。

边界验证覆盖私有查询、加入区间、重建、冻结来源、自身思考清除与多任务独立输入。关联设计见 [记忆](memory.md)、[Agent](agents-and-models.md) 与 [活动](activity-integration.md)。
