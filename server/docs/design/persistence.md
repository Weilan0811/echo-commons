# 数据对象与事务设计

## 1. 权威数据和可重建数据

SQLite 保存社群、身份、成员区间、消息、轮次、任务、角色事实、记忆、图运行及结果。FTS 搜索映射、派生视图和诊断具有各自来源，不决定业务事实是否发生。

用户图像的资产资料、文件规格、引用和生成任务由 SQLite 管理，图片文件存入配置的资产目录；可用记录只引用已经准备好的文件。前端预设图片及清单随前端发布，数据库只保存业务选择的预设编号。文件准备、登记与删除恢复规则见 [图像资产](image-assets.md)。

| 对象群 | 保存对象 | 主要读取与写入边界 |
|---|---|---|
| communities、players | 社群世界时间、运行状态、玩家及社群成员 | 社群服务 |
| character_instances、状态和关系表 | 模板绑定、可用状态、历史状态、当前关系与证据 | characters |
| conversations、memberships、messages 及关联 | 会话、历史成员区间、消息与实际受众 | conversations 与共同观察读取 |
| input_batches、tasks/results | 输入批次及持久执行 | conversations |
| social_chains、social_turns、social_candidates、social_triggers、participation_decisions | 接话链、回应安排、候选进度、触发及实际结果 | social |
| thoughts、memory_*、diary_entries | 私人思考、精确段、摘要、消费、长期记忆和来源 | memory 及审核后的事实服务 |
| reflection_* | 完整快照、节点租约、不可变产物与图结果 | reflection |
| trace_outbox、traces | 业务关联事件与独立投递 | observability |
| realtime_events、realtime_event_state | 已提交变化的引用、单调事件位置及保留边界 | realtime 传输设施与所属业务投影 |
| schema_migrations | 成功应用的结构版本 | 迁移器 |

准确的全部注册表对象、字段、JSON CHECK、主外键及索引见 [数据库参考](../reference/database-schema.md)。这里解释为什么保存，机械参考解释实际存了什么。

## 2. 一次事务的范围

Repository 接收调用方已有的 Connection，不自行提前提交。业务服务控制事务；跨模块事实写入使用同一连接。Database.read 提供一致读取，结束读取事务；Database.transaction 使用 BEGIN IMMEDIATE，正常完成提交，失败回滚并关闭。

| 操作 | 必须一起保存 |
|---|---|
| 实例初始化 | 实例、社群成员、初始状态和记忆副本 |
| 社群创建 | 社群及发起玩家的社群成员关系 |
| 成员操作 | 请求重复检查、成员区间、版本、批次与任务生命周期、原操作结果 |
| 阅读标记 | 可见消息校验与单调已读位置 |
| 玩家发送 | 幂等检查、序号、消息、受众、提及、批次及 trace_outbox |
| 轮次规划 | 精确来源、接话链、候选、单个角色决定与快照、任务额度及角色任务 |
| 对话提交 | 审核结果、完整消息、受众、Thought、零窗口批次、任务结果、链条计数与后续触发 |
| 节点提交 | Artifact、节点状态、前驱绑定及后继激活 |
| 图提交 | 审核、正式事实、消费、覆盖、图结果与终态 |
| 记忆组织 | 长期页、逐页来源、消费及搜索索引 |
| 追踪投递 | trace 去重写入与 outbox 完成 |
| 公开变化 | 所属业务结果与对应实时事件引用；回滚不保留事件，提交后唤醒订阅者 |

模型请求、额度等待和网络重试不持有写事务。提交检查模型执行期间发生的成员、租约、来源及版本变化。需要保存点时，只保护明确的事务子操作；不能通过捕获失败提交半份事实。

实时事件用于传输恢复，业务状态和原来源继续决定事实与可见范围。事件按提交顺序保存，清理后不复用序号；保留窗口与清理边界共同决定游标是否可补充。事件不复制私有内心或模型输入，不代替消息、活动结果及诊断记录。提交后通知与网络发送均在写事务之外，通知失败不改变已提交结果。完整规则见 [实时通信](realtime-communication.md)。

## 3. 约束与错误

数据库保证主键、唯一键、外键、复合归属、枚举及计数 CHECK。多态 ActorRef、JSON 中的业务引用、原成员资格、受众及精确来源由所属服务验证。共用规则经明确接口复用。

客户端幂等、执行尝试结果、图结果、来源消费和租约代次分别对应不同重复路径，不能合成一项“已处理”标记。

业务拒绝可以保存合法拒绝结果，不保存候选事实；实际数据库失败回滚当前事务。StorageError 保留实际原因，HTTP 和任务边界分别转换。某条页面来源无效时，同事务中的页面和消费均不保存。

## 4. 初始结构、迁移和管理

新基线的初始脚本为 0001_initial.sql；0002_social_turn_states.sql 进一步限定社会轮次状态。结构版本与实际 DDL 见数据库参考；`0010_social_continuation.sql` 增加持久接话链，`0011_realtime_events.sql` 增加实时事件及清理边界；`0012_image_assets.sql` 增加资产、文件、引用、生成任务、封面与实例展示版本；`0013_appearance_events.sql` 扩展展示事件，保留已有事件和最高事件序号。迁移保留原业务数据。每份脚本全部成功后才登记 schema_migrations。连接启用外键、busy_timeout，初始化启用 WAL。失败不能保留半份结构及成功版本。

迁移重建被引用的表时，在迁移专用连接的事务外暂停外键检查，提交前执行全库 foreign_key_check；任何错误均回滚。普通业务连接始终启用外键。0002 直接复制有效轮次并保留现有消息和任务引用；若数据库包含正式规划从未生成的 pending 轮次，迁移明确拒绝，不自行猜测它的业务状态。

已投入使用的结构变更使用新增迁移，说明实际数据处理。旧实验数据库及密钥保留；新程序只使用配置中的数据库路径。只读 inspect/export 使用 mode=ro，数据库不存在时明确失败。导出使用 SQLite 备份功能并拒绝覆盖目标，包含数据库中私有信息。

0005 新增人物草稿、AI 候选及自定义固定资源三张表。迁移不改写已有消息、角色、任务快照、记忆或密钥。模型调用在草稿冻结事务之后、候选提交事务之前发生；候选完成与用户接受分开保存。确认人物及草稿状态变更同一事务提交。

本地管理支持按明确社群、草稿、玩家、资产和生成任务范围预览及清理测试数据，具体输入与响应见 [管理接口](../reference/management-api.md#12-测试数据清理)。执行前要求目标社群暂停、相关调用已经结束，并检查范围外的成员关系、人物版本及资产引用。关联记录在一次数据库事务中删除，保持外键检查；失败回滚，不改变范围外数据。

清理提交后唤醒被删除社群的 SSE 连接，结束原范围订阅。资产文件按 [资产删除规则](image-assets.md#6-引用与删除) 恢复清理；预置资源、前端预设、备份、普通日志和显式调试捕获保持各自的管理范围。

结构参考从真实 SQL 初始化及 SQLite 元数据生成，完整 DDL 保留 JSON、CHECK 等不能被字段列表表达的约束。生成检查方式见 [验证指南](../guides/verification.md)。
