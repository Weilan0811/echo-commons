# 角色状态与关系认识

## 1. 归属与读取

角色自身的状态和关系认识属于主观上下文，由 characters 模块保存。一个角色知道另一位角色的公开身份，不会因此获得她的情绪、信任分数或记忆。所有读取和写入都带社群、观察角色和明确目标。两个相同模板的实例拥有独立记录。

availability_status（可用状态）决定运行资格，当前值为 available、offline、busy；StateEntry（状态记录）描述人物自身，包括 physical（身体）、mood（情绪）、activity（正在做的事）。技术超时只影响任务及诊断。

初始化为三种类别分别写入版本 1 的状态，来源为 initialization 及模板版本。默认身体为“无明显不适”、心情为“平和”、活动为“空闲”；模板明确配置时优先采用模板值，格式见 [人物资源](../reference/character-resources.md)。迁移只补充仍为空且没有后续状态版本的初始化记录，保留正式状态和已有非空值。状态反思的提示及触发条件保持原有规则。意图字段的实际支持情况见 [实现状态](../status.md)。

## 2. 状态历史、时间与版本

状态记录包含实例、类别、内容、版本、recorded_at、可选 expires_at 和来源。每种类别独立递增版本。读取时先选观察时刻之前的最新记录，再判断有效期；最新记录过期后，该类别没有当前有效值，不能恢复更早的旧值。

activity 未明确期限时使用记录时间加 24 小时；身体和情绪没有默认期限。读取按 recorded_at、expires_at 的 UTC 时刻及本次观察时间判断；游戏日另外按社群世界时间计算，见 [身份与时间](identity-and-communities.md)。

状态写入在提交事务中按以下顺序执行：事实服务在提交事务中读取该类别的最新记录，把其版本作为 expected_version（期望版本）交给状态规则和存储，再追加下一个版本。期望版本表达本次写入依赖的已保存版本。一次事务处理同类别后续写入时，使用已经更新的版本。

模型的状态反思输出只包含状态类别、内容及允许来源，不携带模型读取时的状态版本。expected_version 由事实服务在提交事务内读取并提供，用于检查本次状态追加依赖的已保存版本。模型输入的冻结身份与状态提交版本分别管理，较早的模型输入本身不构成状态版本冲突。当前事务内版本检查的核实与修复计划见 [D04](../status.md)。

## 3. 有向关系及事实

关系的唯一业务身份是 `(community_id, observer_character_id, target_actor_kind, target_actor_id)`。目标可以是玩家或角色。甲对乙信任增加，只改变甲的记录。关系当前值用于快速读取；RelationshipEvidence（关系证据）追加保存引发变化的具体来源，两者在同一事务更新。

作者确认的共同过去可以在创建实例时建立初始关系，来源为本角色的关系材料。人物编号关联、初始基准和后加入成员的处理见 [人物关系与初始化](character-people-and-initialization.md)。下文的步长规则用于后续日常互动。

| 类型 | 含义 | 三维数值 |
|---|---|---|
| stranger | 尚未建立认识 | 未初始化 |
| acquaintance | 已建立认识 | H=50、T=50、A=0 起算 |
| friend | 已具备朋友资格及分数条件 | 保留已经计算的数值 |

H affection 表示亲近；T trust 表示信任；A attachment 表示依恋。初始化后的数值范围均为 0—100。关系证据引发认识建立后，按基准值计算本次变化。

证据类别包括 interaction（互动）、support（支持）、conflict（冲突）、commitment（承诺）。当前正式策略仅由 interaction 初始化陌生关系；未初始化关系遇到其他类别，不能接受分数或态度变化。成为朋友需要保存支持或承诺资格，且 H、T 均达到 60。依恋变化只在本次证据为支持或承诺时获得实际步长，其他类别步长为零。段反思根据实际行为选择这四类证据，同一人物在同一段中的各维度共用一类；来源资格和选择范围由程序审核。

## 4. 数值变化规则

每个证据可分别影响 H、T、A，每个维度最多一次。方向为 positive、negative、neutral；正负等级为 1—3，中性等级为 0。基础步长依次为 `(0, 1, 3, 6)`，关系类型与维度的系数由 RelationshipPolicy 提供，没有覆盖时为 1。

设当前值为 x、等级步长乘系数为 s：

- 正向变化：`Δ = s × (100 − x) / 100`。
- 负向变化：`Δ = −s × x / 100`。
- 中性变化：`Δ = 0`。
- 新值：把 `x + Δ` 限制到 0—100。

H=50，三级正向、系数 1，结果为 53；三级负向结果为 47。H=90 时，同样的正向变化得到 90.6。距离边界越近，朝该边界的变化越小。全部维度计算后再判断朋友资格。当前规则没有自动降级关系类型的通用策略。

版本只在关系实际改变时递增，记录时间不能倒退。证据类别、目标和来源由运行层从真实材料确定，模型不能自行伪造资格。

## 5. 提交约束与重复处理

运行层检查候选的观察者、目标身份、来源证据、维度、方向、等级和期望版本。关系与状态事实连同反思图结果使用同一连接、同一事务；中途失败全部回滚。

同一来源事件和目标保存一份关系证据，三个维度在同一事务处理。来源身份为 source_kind、source_ref，目标分别保存玩家或角色身份；重复提交已有事件与目标时复用其结果，不再次改变数值。不同目标独立处理。relation_evidence_sources 保存该目标各维度实际使用的新材料合集，character_state_sources 保存每项状态变化的实际新材料；整段覆盖和只读前情不能代替逐项证据。

RelationshipAttitude（关系态度摘要）用文字表达角色对目标的认识，必须保留事实引用。它是可重建的派生视图，不能反过来成为增加分数的证据；正式生成流程属于 [view_refresh](reflection/view-refresh.md)，保存真实证据引用并独立于数值更新。首次有效证据安排初步描述；中性的新证据也记录待刷新变化。数值状态版本、描述刷新进度各按自身事实更新，具体流程及管理恢复见该设计。

## 6. 社群运行例子

Alice 帮小槿甲解决困难，Bob 和小槿乙也在场。甲的反思只能基于自己观察到的消息和自己的 Thought 提出对 Alice 的变化；乙独立反思，可能得到不同认识。两者的来源和观察者不同。Alice 对甲没有自动生成的反向关系分数。

甲后续在另一个会话遇到 Alice，能读取自己的既有关系认识。Bob 请求公开角色列表时，只获得登记和可用状态。关系数据的内部读取不属于公开玩家接口。

字段与索引见 [数据库参考](../reference/database-schema.md)，观察边界见 [角色观察](perspective-and-context.md)。
