# 持久任务、租约与恢复

## 1. 共享机制与独立业务

execution 提供 TaskRegistry、Dispatcher、ModelBudget、心跳、恢复策略和 Supervisor（后台工作管理器）。ConversationQueue 管理回应；ReflectionQueue 管理图节点；ActivityQueue 管理角色游戏行动。各自拥有输入、状态、完成规则和提交服务，不共享万能任务结果。

具体错误分类、恢复动作、审核重试提示及诊断记录的完整规则见 [错误分类、重试与恢复](errors-and-recovery.md)。完整决定由所属业务恢复服务应用；共享策略集中计算等待和次数耗尽，共享记录服务保存正式诊断。

Supervisor 管理共享任务执行器、任务恢复、社交及活动规划、材料准备和追踪投递。工作状态用于健康检查。ActivityQueue 与 ActivityTask 使用自己的活动规则，见[角色行动](activity-actions.md)。

### 全局逻辑队列

`TaskRegistry.register_queue` 登记队列和任务类别，`SchedulingQueue` 在 execution 中统一领取。游戏回合、独立交流、后台整理默认份额为 2:2:1，依次轮询回合、交流、回合、交流、整理。独立交流包含普通聊天、局内回应及表达恢复。回合内的配套发表直接继续原回合，不重新争取轮询机会。

业务队列提供候选、占用范围及等待摘要的角色范围，保留本模块资格校验、节点依赖和租约写入。运行层跳过受阻候选，继续查找同类后续候选；当前类别没有合格任务时跳过。候选领取、租约、诊断和 `execution_scheduling` 中的轮询位置在同一短写事务中提交。全部类别均不可执行时位置不变，重启沿用原位置。份额表示领取机会，已开始的任务继续执行。

同一角色同一游戏参与区间的完整判断按先后执行，已经固定输入的等待判断继续保留该范围，保护意图版本和消息、事件观察进度。同一角色的普通聊天与游戏、不同窗口及不同角色允许并行。独立表达只占用同一窗口同一角色的发表范围，可以与行动判断并行；已经安排的较早表达在重试或等待材料时继续保持发表顺序，后来的表达等待，其他窗口正常执行。social 继续控制交流资格、受众及额度。某次回合的配套发表尚未结束时，本局后续自动行动等待，真人操作沿用正式游戏入口。

共享执行器数量为 `workers.model_concurrency`，替代原三组专用执行器。模型额度仍由 ModelBudget 独立约束，采用相同的类别和权重，在每类内部按等待顺序分配。调度类别通过执行上下文传递给本地决策、普通生成及所需检索；后台向量索引使用整理类别，图像保留独立额度。依赖摘要的等待任务暂不领取，所属角色当前段摘要、连续摘要及其必要图节点继承等待任务的类别，完成后按实际等待状态恢复后台类别。

迁移 36 将迁移 34 的 Activity 专用轮询表改为全局 `execution_scheduling`，清零旧的两类轮询位置。业务任务和保存的阶段结果保持原记录，没有增加任务副本或业务表。

## 2. 领取与完整执行

队列在短写事务中检查任务状态、可执行时间和业务资格，领取并增加 attempt 与 lease_generation。租约保存 owner、代次、尝试次数和截止 UTC 时间。同一 owner 再次领取也属于新代次。取得写事务后读取一次实际 UTC 时间，该事务内的资格复核、租约、状态更新和诊断记录共用这次时间；进入后台线程前的调度时间不用于提交。反思视图扫描与初始化推进也在写事务内取得材料截止时间，证据与正式状态在同一边界读取。等待和超时使用持续计时，社群世界时间不参与租约判断。

1. 读取原持久输入，启动心跳。
2. 等待共享模型额度，等待期间继续续期；新的 Activity 判断在取得名额后准备时效性输入。
3. 实际模型请求前复核租约及当前业务资格。
4. 在写事务之外执行模型和只读工具。
5. 提交事务复核 owner、attempt、generation、期限、来源及资格，保存事实或重试决定。

心跳间隔必须小于租约期限减安全余量。心跳读取到终态后停止续期。失去租约时停止当前执行；迟到结果被拒绝。attempt 表示一次完整执行尝试，供应商内部请求不增加持久任务代次。

Activity 判断与独立表达使用 `ModelBudget.reservation`，取得模型名额后才准备时效性现场。实际生成前读取当前有效租约的截止时间，等待期间续期后可以正常开始生成。同一次串行生成的模型请求和工具检索复用该名额；后台任务在其他执行上下文中仍申请名额。结束、取消或准备失败释放名额。需要等待检索或摘要时保存输入准备阶段并延期，队列仅领取材料已准备好的任务；`memory_summary_pending` 不消耗该任务表中的尝试次数。已经形成的决定和正文按原阶段恢复。

## 3. 对话状态与生命周期

对话任务状态为 pending、processing、retry_wait、suspended、completed、failed、cancelled。pending 和到期 retry_wait 可以领取；processing 只能由有效租约执行；暂时失败按退避继续；预算耗尽进入 failed。合法沉默进入 completed，结果 outcome 保留沉默含义。

| ConversationTask.status | 进入原因 | 可以继续怎样处理 |
|---|---|---|
| pending | 已保存任务；等待主动任务在实际安排时准备快照 | 输入准备完成且资格满足时领取为 processing |
| processing | 取得有效租约 | 提交成功、有限重试、终态失败或业务取消 |
| retry_wait | 可重试失败，保存下一次可执行时间 | 到期并满足资格后以新代次 processing |
| suspended | 社群暂停 | 恢复后继续原任务，不重选输入 |
| completed | 发言已批准保存，或合法沉默 | 终态；重复提交返回原结果 |
| failed | 不可重试失败或预算耗尽 | 终态；后续新输入可以建立新任务 |
| cancelled | 会话归档、原成员资格失效或轮次额度耗尽时取消等待安排 | 终态；迟到结果不得写入 |

队列处理领取和租约，任务执行器形成重试或失败决定，业务服务处理暂停和取消，提交服务负责保存合法终态。attempt 与 lease_generation 是尝试身份和租约代次，不增加新的任务状态。模型一次供应商重试不创建新的 ConversationTask。

社群暂停把对话任务转为 suspended，恢复后继续规划。等待主动任务尚无上下文，实际安排时准备输入；已经准备的任务和重试复用冻结快照。新玩家消息加入当前群聊轮次，生成中的角色可以完成表达，观察进度只记录本次实际输入截止。沉默或最终失败后，规划器按每名角色自己的新内容继续选择。会话归档和原角色成员资格失效会取消对应任务。领取、每次模型请求前和提交继续检查任务与轮次有效性，规则见[会话设计](conversation-and-social.md)。

反思使用独立节点和图状态，详见 [反思执行](reflection/execution-model.md)。当前暂停及资格处理不能仅从对话机制推断反思具有同样生命周期覆盖，具体实现范围见 [状态说明](../status.md)。

## 4. 启动恢复与关闭

过期 processing 租约转为 retry_wait 或超过预算后的 failed；未过期租约保留到期时间，后续恢复检查继续处理。新的领取使用原任务及快照、新尝试和代次。恢复不重新选择输入材料。

Supervisor 关闭先停止领取，等待配置期限完成在途工作，必要时取消剩余后台调用，再关闭模型客户端与数据库资源。未提交的执行由持久租约恢复，不保存虚构成功。

## 5. 真实过程例子

执行器甲领取对话任务并开始网络请求，进程退出。数据库仍保存 processing 和租约期限。重新启动后，期限到达，执行器乙以新代次读取原快照；甲迟到结果因旧代次拒绝。乙成功提交一次发言，参与决定完成。追踪投递暂时失败不会让甲或乙重新生成这条发言。

按 [验证指南](../guides/verification.md) 分别验证领取、续期、旧代次、退出重启和业务取消。图级 partial 补充恢复用于复用成功产物并重新执行失败的可选分支，通过正式重新启动入口创建补充运行；与已有节点租约恢复分别说明。对象状态之间的关系见 [生命周期归属](object-lifecycles.md)。
