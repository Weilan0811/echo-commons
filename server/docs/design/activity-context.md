# 活动输入与局内工作记忆

更新日期：2026-10-29。Activity 单元 4.2 已实现输入准备、保存、恢复和理解登记。活动任务安排、自动行动、正式发言提交及生命周期联动按[实施计划](../../../docs/06-activity-implementation-plan.md#73-活动任务与角色行动)继续实现。

## 输入准备

`Application.activity_context` 提供三个异步入口，均接收社群、角色、游戏和稳定的 `input_id`：

| 入口 | 必要来源 | 专属材料 |
|---|---|---|
| `prepare_turn` | 当前实际行动机会 | 正式机会与对应玩法分析 |
| `prepare_reply` | 尚未处理的可见聊天 | 待理解消息及原始交流 |
| `prepare_reaction` | 尚未处理的可见游戏事件 | 本次事件及局势 |

三种输入组合共同人物材料、当前状态和关系、已有记忆、原参与区间可见的游戏观察、相关聊天、局内工作记忆和自身已经保存的简短内心。回应与事件反应不携带行动机会或候选分析。行动分析通过[玩法注册表](game-analysis.md)选择实现，恢复时使用相应正式动作类型。

准备在同一只读事务中固定参与编号、成员区间、游戏版本、事件读取上限、消息上限、工作记忆版本和来源。人物、关系、状态与记忆读取复用普通会话的共同准备能力；当前局内会话严格限制为本次成员区间。待理解消息、其回复对象和当前意图引用的可见约定保留完整原文；其他近期背景沿用已有摘要、检索和裁剪规则。

冻结材料保存后，向量检索、人物精简和游戏分析在写事务之外执行，分别保存阶段结果。相同 `input_id` 恢复原材料与已经完成的阶段；参数不同会报告冲突。新消息通过新的输入处理。`restore` 可以读取原输入，包括对局结束后的诊断读取；后续正式执行仍须重新检查资格。

## 两种模型材料

普通角色调用保留完整人物资料。本地判断使用 `decision_persona`：短资料直接使用，较长资料通过现有模型路由 `activity_persona` 精简，未指定时使用默认模型。精简调用共享模型额度和凭据，保存真实请求、响应与用量。

精简缓存依据人物资源编号、来源版本、精简契约版本和字符预算复用。人物资源变化会使用新的缓存身份；当前情绪和关系每次独立读取。精简缓存只包含静态人物资料。

`tasks/prompt.py` 为两种路径组织材料，保留规则事实、搜索估计、聊天原文和角色主观材料的来源。`current_input_sources` 列出当前聊天编号与真实消息编号的映射，以及本次待处理标记。准备检查两种材料的完整字符预算；正式投影另将输出结构和工具说明计入预算。必要材料超出预算时明确失败，保留待处理来源。

## 理解与处理位置

准备输入不会推进消息或事件的处理位置。调用者产生 `ActivityUnderstanding` 后，通过 `record_understanding` 保存实际理解：逐条消息含义、确切事件编号和可选的简短内心。来源必须与原输入中的待处理消息和可见事件完全相符；重复、遗漏或额外来源均被拒绝。

理解结果和处理位置在同一短事务保存。另一个输入已推进位置时报告冲突；相同结果重复登记保持原结果。输入冻结后到达的消息仍然待处理。角色内心来自实际理解结果，单条最多 1000 字符；供应商内部推理不作为角色内心写入。自动安排理解及联合行动输出由后续活动任务接通。

## 意图范围与生命周期

`Application.activity_working_memory` 按 `(community_id, character_id, game_id, participation_id)` 保存当前意图。每条意图记录内容、真实消息引用及最初产生它的输入编号。`replace` / `replace_in` 接收完整目标列表与预期版本，可以继续、修改或结束意图；消息引用只能来自该次最终输入的可见聊天。相同输入不能写入不同结果。

只有进行中的对局和活动会话提供当前意图。暂停保留存储，恢复和重启继续读取；重新参与使用新的参与编号。结算或会话归档后，当前读取返回空值，新的赛后输入不携带意图。`clear_in` 提供明确删除入口，供后续生命周期事务接通。

当前意图只用于本局活动判断；普通聊天、赛后交流、经历整理和长期检索不读取这份工作记忆。冻结输入保存的是当时依据，删除当前意图不会改写历史输入。游戏结束、取消、退出和归档时的自动删除联动属于 4.3、4.4，尚未接通。

## 数据与配置

迁移 30 新增 `activity_inputs`、`activity_working_memory`、`activity_observation_progress` 和 `activity_persona_projections`，保留原有数据。社群清理包含前三张表；删除自定义人物草稿时包含相应精简缓存。

`[activity]` 配置控制完整输入预算、人物直接使用阈值、精简预算、每次事件数量和近期内心数量，字段及默认值见[配置参考](../reference/configuration.md)。输入准备尚未增加公开 HTTP 接口和后台活动任务。
