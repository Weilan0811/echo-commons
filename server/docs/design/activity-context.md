# 活动输入与局内工作记忆

更新日期：2026-11-06。输入准备、保存、恢复和理解登记已接入[正式活动行动](activity-actions.md)与[局内回应](activity-coordination.md)。正式发言与[游戏经历](activity-memory.md)已接入共同模块。

## 输入准备

`Application.activity_context` 提供三个异步入口，均接收社群、角色、游戏和稳定的 `input_id`：

| 入口 | 必要来源 | 专属材料 |
|---|---|---|
| `prepare_turn` | 当前实际行动机会 | 正式机会与对应玩法分析 |
| `prepare_reply` | 尚未处理的可见聊天 | 待理解消息及原始交流 |
| `prepare_reaction` | 尚未处理的可见游戏事件 | 本次事件及局势 |

三种输入组合共同人物材料、当前状态和关系、已有记忆、原参与区间可见的游戏观察、相关聊天、局内工作记忆。跨回合的当前打算通过局内意图延续；真实内心作为[游戏经历来源](activity-memory.md)参与摘要和认知整理。回应与事件反应不携带行动机会或候选分析。行动分析通过[玩法注册表](game-analysis.md)选择实现，恢复时使用相应正式动作类型。

首次准备在同一短事务中读取并保存参与编号、成员区间、游戏版本、事件读取上限、消息上限、工作记忆版本、回应进度和来源关联。人物、关系、状态与记忆读取复用普通会话的共同准备能力；当前局内会话严格限制为本次成员区间。待理解消息、其回复对象和当前意图引用的可见约定保留完整原文；其他近期背景沿用已有摘要、检索和裁剪规则。检索、人物精简、分析及模型调用在事务外进行。

冻结材料保存后，向量检索、人物精简和游戏分析在写事务之外执行，分别保存阶段结果。相同 `input_id` 恢复原材料与已经完成的阶段；参数不同会报告冲突。新消息通过新的输入处理。`restore` 可以读取原输入，包括对局结束后的诊断读取；后续正式执行仍须重新检查资格。

## 任务状态与身份

活动输入的 `session_context` 保存本局游戏与规则、本人参与编号，以及按稳定人物身份逐项保存的名称、席位和本人标记。同名人物保留独立记录；这部分由 Activity 组合游戏和参与关系数据。

模型输入使用以下层级，普通判断和本地判断共用结构：

| 标签 | 内容 |
|---|---|
| `task_state/session_context` | 本局身份、规则与胜利条件、参与者、席位及正式结果对应 |
| `task_state/current_game_state` | 游戏版本、阶段、行动方、棋盘及本次行动机会 |
| `task_state/current_intents` | 当前局内意图与实际消息依据 |
| `task_state/communication_state` | 聊天编号、真实消息身份、待理解标记、近期自身发言引用、表达资格及回应安排 |
| `formal_observation` | 原判断读取的正式事件、时间及处理范围 |
| `action_analysis` | 行动候选、规则后果和分析估计，仅行动任务提供 |

固定身份和指令前置，任务状态随后提供，相关记忆和按顺序组织的对话继续由共同上下文负责。合法动作按类型列出参数名 `fields` 及对应的合法参数行 `values`，完整保留合法选择，同时减少重复字段。

表达准备重新读取人物与席位对应，其 `current_game_state` 使用表达准备时的游戏观察。独立表达的当前聊天与原决定分别保存时间、读取截止和来源版本，既有正文继续绑定原输入。详细准备及恢复规则见[局内表达](activity-expression.md#独立表达的现场与原决定)。

新行动与接话输入的提示布局版本为 2，独立表达为 3，共同聊天输入为 3；旧版本和缺少新增可选字段的冻结记录继续按原字段恢复。原始事件正文、来源编号和游戏规则保持原定义。共同身份与标签约定见[提示契约](character-prompt-contracts.md#4-身份规则的共同说明)。

## 两种模型材料

普通角色调用保留完整人物资料。本地判断使用 `decision_persona`：短资料直接使用，较长资料通过现有模型路由 `activity_persona` 精简，未指定时使用默认模型。精简调用共享模型额度和凭据，保存真实请求、响应与用量。

精简缓存依据人物资源编号、来源版本、精简契约版本和字符预算复用。人物资源变化会使用新的缓存身份；当前情绪和关系每次独立读取。精简缓存只包含静态人物资料。

`tasks/prompt.py` 为两种路径组织材料，保留规则事实、搜索估计、聊天原文和角色主观材料的来源。`communication_state` 列出当前聊天编号与真实消息编号的映射，以及本次待处理标记。准备复用共同上下文选择，检查两种请求的模型容量与字符预算，将输出预留、输出结构和工具说明一起计入。历史需要摘要时等待已有反思任务，保留原读取截止与已完成的准备阶段，不消耗模型尝试次数。必要材料超出预算时明确失败，保留待处理来源。

## 理解与处理位置

首次请求尽量预留输入上限的八分之一、最多 4000 字符，用于后续工具结果与输出修正。事件条数是批次上限；完整请求超出容量时减小事件批次，原游标保留尚未处理的事件。单个事件及当前必要材料已经占满容量时，预留空间随实际余量缩小，总容量限制保持不变。冻结完成后的快照确定实际处理范围，后续登记使用该快照中的事件和游标。提示中的回应进度只保留当前安排、待表达安排和本次可见消息的处理状态；内部安排编号仍保存在冻结记录中。

准备输入不会凭空推进消息或事件的处理位置。调用者产生 `ActivityUnderstanding` 后，通过 `record_understanding` 保存实际理解：逐条消息含义、确切事件编号和可选的简短内心。来源必须与原输入中的待处理消息和可见事件完全相符；重复、遗漏或额外来源均被拒绝。本地直接选择的正式提交也推进其已经读取的冻结来源，保留实际选择记录，文字理解与内心保持空值。新输入准备可补齐已提交选择的处理位置；当前输入退出待处理列表后仍按共同历史规则参与后续判断。

理解结果和处理位置在同一短事务保存。另一个输入已推进位置时报告冲突；相同结果重复登记保持原结果。输入冻结后到达的消息仍然待处理。角色内心来自实际理解结果，单条最多 1000 字符；供应商内部推理不作为角色内心写入。普通行动的理解、意图、正式动作、回执和真实内心共同提交，规则见[角色行动](activity-actions.md)。

## 意图范围与生命周期

`Application.activity_working_memory` 按 `(community_id, character_id, game_id, participation_id)` 保存当前意图。每条意图记录内容、真实消息引用及最初产生它的输入编号。`replace` / `replace_in` 接收完整目标列表与预期版本，可以继续、修改或结束意图；消息引用只能来自该次最终输入的可见聊天。相同输入不能写入不同结果。

首次保存工作记忆使用版本 1，目标意图为空时也登记本次输入。此后意图内容及来源集合相同时，沿用原编号、最初输入和版本。仅调整列表或来源顺序、重复同一项及首尾空白不构成变化；新增、结束、修改内容或来源集合会增加版本。`last_input_id` 继续登记本次提交，表达生成和发表不再调用意图更新入口。

只有进行中的对局和活动会话提供当前意图。暂停保留存储，恢复和重启继续读取；重新参与使用新的参与编号。游戏结算、取消、角色退出和会话归档会清除当前工作记忆，新的赛后输入不携带意图。正式业务生命周期、后台扫描和启动恢复共同检查这些边界。

当前意图只用于本局活动判断；普通聊天、赛后交流、经历整理和长期检索不读取这份工作记忆。冻结输入保存的是当时依据，删除当前意图不会改写历史输入。

## 数据与配置

迁移 30 新增 `activity_inputs`、`activity_working_memory`、`activity_observation_progress` 和 `activity_persona_projections`，保留原有数据。社群清理包含前三张表；删除自定义人物草稿时包含相应精简缓存。

`[activity]` 配置控制完整输入预算、人物直接使用阈值、精简预算、每次事件数量，字段及默认值见[配置参考](../reference/configuration.md)。后台行动使用这些输入，管理详情提供原输入诊断读取。
