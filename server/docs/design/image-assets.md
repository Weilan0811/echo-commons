# 图像资产与生成

本文定义用户图像的生成、上传、保存、引用和删除。当前实现状态见 [状态](../status.md)。前端预设图片及清单随 `frontend/public/assets/` 发布；后端只保存业务选择的预设编号。

## 1. 对象与模块职责

`modules/assets/` 负责资产归属、用途、引用和生图任务。接口层校验请求并返回类型化结果；后台执行层安排生成、查询供应商任务及恢复；存储设施负责图片处理和文件读写；供应商设施负责 APIMart 协议。人物和社群服务通过明确入口选择资产。

| 对象 | 保存内容 |
|---|---|
| 图像资产 | asset_id、所属 player_id、用途、upload/generated/derived 来源、创建时间；裁剪资产另存来源资产编号与裁剪区域 |
| 图像文件 | 用途标准图及展示档位、相对文件路径、MIME、实际宽高、字节数 |
| 生成任务 | 请求编号、所属玩家、用途、冻结输入和最终提示、请求参数、供应商 task_id、状态、结果或错误 |

用途为 `character_illustration`（角色插画）、`character_avatar`（裁剪头像）、`community_cover`（社群封面）、`chat_background`（聊天背景）。一个生成任务产出一张图片及其展示档位，成功结果引用一个 asset_id。角色任务先产出带背景的胸像到半身完整插画，玩家确认方形取景后另存头像资产；头像保存来源插画及裁剪区域。聊天背景使用一张横图，窄屏由前端中心裁切。图片与任务属于玩家；资产资料、任务和删除操作检查所属玩家。展示图片按资产编号读取，响应只包含图像。身份沿用当前 player_id 体系。

用户资产由后端管理，官方素材由前端发布。前端通过稳定的资产读取 URL 使用图片，不依赖磁盘路径或供应商临时下载地址。存储入口只表达保存、读取、删除，当前采用本地目录。

## 2. 上传与文件规格

上传接受 multipart（文件表单）。按实际图片内容解码并检查 WebP、PNG、JPEG；只接受单帧位图。角色插画上传上限 5 MiB，封面与聊天背景上传上限 8 MiB，解码后像素上限 2400 万。生成结果下载上限 32 MiB，并检查相同的格式和像素限制。上传角色图片先保存完整插画，头像通过玩家确认的方形取景另存。

Pillow 负责解码、方向处理、尺寸调整及 WebP 编码。用户生成规格由用途固定，前端请求不提供分辨率选项。上传图片保留实际比例，超过用途目标边界时等比缩小，小图不放大，响应提供实际宽高。角色插画带完整环境背景，人物与背景一起展示，处理流程保留背景。头像从插画取景，保留肩颈和局部环境。

| 用途 | 用户图片标准规格与展示档位 |
|---|---|
| 角色插画 | illustration.webp：1080×1350，另提供 540×675 的预览档；上传图保留比例，适配这两个尺寸边界 |
| 角色头像 | avatar.webp：512×512，另提供 256×256 档；小于目标尺寸的选区保留实际尺寸 |
| 社群封面 | cover.webp：1600×600，另提供宽度 768、1536 的展示档；上传图在 1600×600 边界内等比缩小 |
| 聊天背景 | background.webp：1920×1080，仅提供这一标准档；上传图在此边界内等比缩小 |

文件存入配置的资产目录，默认 `server/data/assets/images/{asset_id}/`。全部持久图片转码为 WebP；完整插画、头像、封面和背景分别保存为 illustration.webp、avatar.webp、cover.webp 和 background.webp，其他档位按宽度命名，例如 illustration-540.webp、avatar-256.webp 和 cover-768.webp。标准图是后续展示与头像取景的来源。供应商下载文件和用户上传文件只用于临时处理，转换成功后删除；不保存超出用途规格的原始文件。SQLite 保存每份文件的档位、相对路径和属性，资产对象继续采用一项资产对应多份展示文件的结构。

1080×1350 插画的建议初始取景为 x=0、y=0、size=1080；其他尺寸使用画面上部、边长为宽高较小值的正方形。人物生成构图将脸部放在上部取景的中央附近，保留头顶、左右头发和发饰，并带少量肩颈。初始取景供前端裁剪框使用，玩家确认后才创建头像资产。

前端显示完整插画并允许玩家移动、缩放方形裁剪框。确认后提交来源插画 asset_id 和基于 illustration.webp 实际像素的 x、y、size，前端把显示坐标转换为图片坐标。后端复核归属、来源用途、正方形尺寸及边界，裁剪并导出 512、256 两档 WebP，保存独立头像资产，返回其来源插画和规格。每次确认使用独立请求编号避免重复保存；重新裁剪产生新头像，保留完整插画与已有头像。更换角色肖像时通过选定头像的来源关联同时更新公开头像与插画，业务引用在一个事务中修改。

官方角色的 illustration.webp 与 avatar.webp 按同一规格制作，头像在素材制作阶段逐张检查取景后随 frontend/public/assets/ 发布。前端运行时直接展示两份成品，角色图片沿用完整背景。官方素材不进入用户资产存储。

官方聊天背景以 3840×2160 为制作基准，官方社群封面以 3200×1200 为制作基准，随前端发布并由前端提供展示档位。用户图片采用本节标准；后端封面档位为 768、1536，聊天背景只有 1920×1080 横图。窄屏展示在前端采用横图中心裁切。

处理期间使用资产目录下的临时目录。文件完成后移入正式目录，再在短事务中登记可用资产；登记失败删除本次文件。启动维护清理中断留下的临时文件，并依据任务及资产记录处理未登记文件。文件系统操作与 SQLite 提交分别完成，可用记录只引用已经准备好的文件。

资产内容创建后不覆盖；重新上传或生成取得新的 asset_id。图片读取带明确 Content-Type、Cache-Control 和 X-Content-Type-Options: nosniff。元数据和任务响应不包含供应商凭据。

## 3. 公共提示与生成风格

提示保存为包内资源：

| 路径，均相对 resources/ | 职责 |
|---|---|
| prompts/assets/common.md | 通用画面要求、避免绘制文字、线条与上色规范 |
| prompts/assets/character_illustration.md | 4:5 完整插画、安静自然的胸像到半身、默认表情、头部安全空间及上部方形头像取景 |
| prompts/assets/community_cover.md | 8:3 横幅、明确世界观、可辨识的场景与主体、标题安全区 |
| prompts/assets/chat_background.md | 16:9 中性环境、中部暗且空、边缘细节、中心裁切及压暗模糊后的可读性 |
| assets/generation_styles.yaml | 稳定风格编号、展示名称、说明和生成风格正文 |

最终提示依次组装：公共要求、用途要求、选定画风、选定场景环境、本次人物或场景描述。生成任务保存完整组装结果和实际请求参数；公共资源修改后，已有任务继续使用冻结输入。画风清单通过后端查询提供，前端选择风格编号。

画风预设负责笔触、线条和上色；前端场景预设负责环境、时间、光照和色彩。前端随包场景清单提供 preset_key、time_of_day、lighting、palette、background_description，生成请求传入选定场景的这些材料，后端校验后冻结为 scene_context。后端不复制前端场景清单，也不读取前端素材目录。

社群封面用于世界选择卡片及社群头部，依据明确提交的世界或场景描述生成，例如深夜食堂、校园黄昏。画面允许具体、明亮和有辨识度，构图预留标题区域。每个社群通过封面引用选择一张图片。

聊天背景铺满聊天页并长期位于文字与界面下面。画面为中性聊天环境，场景材料只描述环境、时间、光照与色彩；生成输入不自动读取社群世界设定。中央保持暗且空，细节集中在边缘，并为窄屏中心裁切保留安静的中心区域；经过前端压暗和模糊处理后仍保持整体氛围。默认背景随前端发布，用户可以生成或上传自己的聊天环境。

角色公共构图要求：一个默认表情，胸像到半身，姿态安静自然；背景虚化，人物与背景光影一体，四周压暗，视觉重心在画面中上部，头顶与左右预留安全空间。用途提示要求背景符合 scene_context，时间与灯光来自场景预设。夜景预设使用对应夜间环境及光源；白天预设采用对应日间环境。暖色场景沿用预设的暖色光照，使同一张插画适合深色卡片和暖纸拍立得展示。头像选区不能切断头部或发饰。

人物生成可使用作者明确提交的描述，或所属草稿的公开人物描述与指定外貌要求。请求期间冻结草稿编号及 revision；不自动读取角色的私人内心、关系、运行记忆或完整采访。生成结果作为可选预览，作者确认选择后才改变业务引用。

## 4. APIMart 异步生成

供应商请求为 `POST https://api.apimart.ai/v1/images/generations`，模型为 `gpt-image-2`；提交后返回 task_id，通过 `GET /v1/tasks/{task_id}` 查询结果。协议依据为 [生成说明](https://docs.apimart.ai/cn/api-reference/images/gpt-image-2/generation) 与 [任务查询](https://docs.apimart.ai/cn/api-reference/tasks/status)。

生图路由和凭据引用由非秘密配置定义，引用名为 `apimart`。运行时复用现有凭据加载机制，从配置的 model-secrets.toml 的 `[credentials]` 读取；示例文件提供 `apimart = ""`。凭据不进入任务、提示、公开响应或日志。

一个生成任务提交一次单图请求，n=1、resolution=1k；按用途固定 size 的像素尺寸：角色插画 1080x1350、社群封面 1600x600、聊天背景 1920x1080，对应比例为 4:5、8:3、16:9。请求参数由后端决定并保存，玩家只选择用途、画风和内容。供应商结果需要检查实际尺寸与比例，足够大的同用途比例图片缩小到标准规格；小于目标尺寸或比例不符的结果报告明确错误，保持实际生成质量。后台生图并发默认 1，与聊天、创作和反思的文字模型额度分别管理。供应商任务每 5 秒查询一次，总期限默认 900 秒，单次网络请求期限 30 秒；这些参数由生图配置管理。

客户端请求编号用于重复检查：同编号同输入返回原任务，同编号不同输入拒绝。任务状态表达排队、提交、供应商生成、图片保存、完成和失败；标准图片及展示档位登记完成后任务成功，返回一个正式 asset_id。角色任务返回插画资产，头像通过独立裁剪请求创建。网络请求和图片处理期间不持有数据库写事务。

获得供应商 task_id 后立即持久保存，重启继续查询同一任务；结果下载和保存恢复也使用该任务。提交请求已发出但未能确认供应商任务编号时，记录提交结果未知，停止自动重新提交，避免重复生成与计费。缺少凭据在申请阶段明确报告环境不可用，不生成替代结果；失败任务保留错误，显式新请求才创建新任务。

前端通过任务查询获得进度，有未完成任务时短期轮询，结束后停止。任务可在人物草稿阶段创建，不要求属于社群；社群 SSE 不承担生图任务进度。

## 5. 业务引用与展示

社群保存可空 cover_kind 与 cover_ref：同时为空表示未选择，preset 引用前端稳定编号，asset 引用可用的社群封面资产。创建和封面修改都支持这些字段；修改检查 state_version，实际变化增加版本。后端校验预设编号的格式，清单与图片存在性由前端管理。

草稿和固定人物资源的用户头像通过 avatar_asset_id 引用裁剪资产；原有外部 avatar_url 保留实际支持行为，写入只选择一种来源。公开 avatar_url 由共同展示读取解析，illustration_url 从该头像的来源插画解析；官方角色可由模板提供前端随包插画地址，外部头像没有关联插画时为空。生成的 URL 不充当资产身份。人物定稿固定默认头像引用，复制草稿继续保留同作者的引用。

实例可以保存独立头像覆盖及展示版本，清除覆盖恢复固定人物默认头像；设置不修改三份人设正文或固定人物版本。社群成员可以修改该社群角色的展示头像，选用资产必须属于发起玩家且用途为角色头像。角色、会话参与者、消息发送者等公共展示共用同一读取入口。

封面修改与角色展示修改各发送对象级变化通知，社群成员重新查询相关公共对象；通知使用现有持久 SSE 机制。已保存消息正文、来源与受众不因展示变化而改变。聊天背景资产支持生成、上传和读取，具体背景偏好绑定由对应界面需求定义。

## 6. 引用与删除

草稿、固定人物资源、实例覆盖及社群封面分别登记实际资产引用，业务更新与引用更新同事务保存。裁剪头像登记对来源插画的引用；头像仍存在时不能单独删除其来源插画。外部 URL 和前端预设不登记为用户资产。

更换图片解除旧引用，保留旧资产供所属玩家再次选择或删除。删除接口只接受所属玩家未被引用的资产；仍有引用时返回冲突。固定资源的默认头像持续属于有效引用，即使某个实例采用覆盖头像也不解除它。

删除先保存不可再绑定的删除状态，再移除文件并完成记录清理。维护操作删除所属玩家时，已进入删除状态的资产允许暂时解除所属玩家外键，随后完成文件和记录清理；可用资产必须拥有玩家。中断由启动维护继续处理。测试维护允许清理明确指定的未引用资产及生成任务，规则见 [持久化设计](persistence.md#4-初始结构迁移和管理)。前端预设素材不进入此流程。
