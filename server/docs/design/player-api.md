# 玩家读取、阅读位置与成员操作

## 1. 身份与范围

当前为本地测试模式，`player_id` 表示选定玩家。玩家通过 `/api` 发现身份、社群、公共参与者和自身会话，管理通过 `/internal` 取得完整对象列表、成员历史和私人材料。对象范围与账户凭据分别承担职责，当前没有账户认证。

创建社群时在同一事务加入发起玩家；角色与会话创建要求发起者属于社群，会话还必须包含发起者。初次会话成员由创建或管理操作建立，玩家自身加入用于恢复已经参与过的会话。

角色公共名字来自实际绑定模板版本，可空 `avatar_url` 由共同展示读取解析实例覆盖或固定默认头像，`illustration_url` 指向完整来源插画或模板指定的官方插画，没有关联时为空；用户资产引用和原有外部地址遵循 [图像资产](image-assets.md#5-业务引用与展示)。社群封面响应提供可空 cover_kind 与 cover_ref，前端解析预设图片或读取用户资产。公共展示投影不包含私人上下文。系统消息保留独立来源和系统标签。

## 2. 一份可见规则

成员区间覆盖消息序号，且该区间实际属于消息受众时，主体能够观察消息。重新加入不会获得离开期间的消息。消息读取、最新历史、会话预览、未读、回复引用与 SSE 消息投影采用这份规则；SQL 查询条件集中在 `modules/perspective/policy.py`，与正式对象观察规则表达相同判断。

玩家会话查询按真实参与历史筛选，默认当前活跃会话，可筛选历史和归档。离开后仍能读取旧经历；当前名单要求当前成员资格。概要一次返回自身成员状态、发送资格、私聊对方、最后可见消息和阅读位置，不要求页面逐个查询成员。

会话按玩家可见最后消息时间排序，没有消息时使用创建时间，同时间按编号确定顺序。不可见私人消息不改变其他玩家的摘要、排序与未读。对象列表使用普通分页，刷新从第一页开始并按编号去重。

## 3. 查询与事件读取位置

对象列表的 `cursor` 绑定查询和筛选范围；结束时为空。消息增量游标保存已扫描序号，无新消息时仍返回有效游标；一页限制扫描数量，经过过滤可以为空但仍有下一页。

历史接口首次取得最新可见消息，固定扫描终点，按序号升序返回。`older_cursor` 继续查询更早可见消息，`has_older` 表示还有更早内容。首次 `poll_cursor` 接在扫描终点之后，用于现有增量读取；后续历史页该字段为空。空历史也有有效增量位置。

历史数量按可见消息限制，实际私有尾部不会隐藏较早可见消息。游标各自使用，不能互换，也不能跨玩家、会话或筛选条件使用。历史固定扫描终点，每次读取仍检查实际范围。

SSE 事件游标绑定玩家与社群，记录已扫描的提交事件位置，与消息增量和历史游标分别管理。初次加载先取得事件位置，再读取现有查询，以原事件位置订阅补充变化。事件去重使用事件位置，消息去重使用 message_id；恢复流程见 [实时通信](realtime-communication.md)。

单条消息和引用预览按读取身份校验。不可见引用保留已有来源编号，正文和展示预览为空。当前成员可以回复自己可见的旧区间消息，发送事务重新检查当前发送资格与提及。历史私有消息提供发生时实际接收主体公共信息，公共消息不携带完整受众区间。公开轮次仅返回玩家可见的精确输入编号。

## 4. 阅读位置

`conversation_read_positions` 按玩家与会话保存已读序号，更新取原值与请求值的较大者。请求提供已展示消息编号；服务检查属于会话并可见后取得序号。多个标签页提交较旧位置不会倒退。

未读统计阅读位置之后、实际可见且发送者为其他主体的消息，不用全局序号相减。HTTP 查询与接收推送均不标记已读；玩家实际查看消息后提交阅读位置。已读变化只通知该玩家，事件接收位置不代替阅读位置。离开后可以推进旧经历的阅读位置，重新加入保留原记录并排除离开期间消息。

旧数据没有可靠阅读记录，默认位置为 0；不补造曾经阅读的事实。

## 5. 成员写入

`ConversationService` 维护正式成员变更；玩家与管理路径共用该服务。玩家只能加入和退出自身，退出提供 `expected_membership_id`；管理操作指定玩家或角色，提供 `expected_membership_version`。

`client_operation_id` 标识一次成员请求，玩家编号以发起玩家为范围，管理编号以社群管理来源为范围。正式操作表保存规范请求与原结果。检查顺序为对象归属、原请求重复、当前资格与期望值、实际写入与结果保存。相同编号和内容返回原结果，不同内容返回 `idempotency_conflict`。版本或区间不符分别返回明确冲突，整个事务不修改成员与版本。

成员变化、版本更新、收集批次封闭、任务生命周期和原结果同一事务完成。已经活跃的加入不创建新区间、不增加版本；离开后重新加入创建新区间。重复退出即使发生在重新加入之后，也只返回保存的原响应。

直接会话固定最初的一个玩家和一个角色；活跃成员可以暂时零个或一个，恢复各自区间不依赖加入顺序。旧身份替换保留历史，后续加入恢复原始身份，读取仍按真实经历。消息发送使用自己的 `client_message_id`，已读通过单调位置实现幂等，三者分别表达各自请求语义。

实际路径、字段和错误见 [HTTP 参考](../reference/http-api.md)、[管理接口](../reference/management-api.md) 和 [OpenAPI](../reference/openapi.json)。

## 新消息的会话范围

发送请求不接受 `visibility` 或 `recipients`。后端保存发送时的全部当前成员区间；`mentions` 表示提及，不能缩小受众。私聊使用独立直接会话，与部分成员交流使用包含这些成员的群聊。公开读取中的范围与接收主体字段用于解释历史记录和旧轮次回应，详细契约见 [HTTP API](../reference/http-api.md)。
