# 本地 SQLite 与持久任务

状态：生效。基线版本：`0.1.0`。

## 决定

服务使用单进程与 SQLite。数据库保存权威业务状态和持久任务；写事务保持短小，真实模型调用在事务之外执行。

## 实际影响

部署与开发容易理解，进程重启通过租约恢复。多节点服务需要另行设计存储与分派机制。

实现依赖见 [系统设计](../design/system.md)，字段约束见 [数据库](../reference/database-schema.md)。当前差异与审核状态见 [状态说明](../status.md)。

## 背景与成立条件

当前运行目标是本地单进程平台，业务需要消息顺序、多人任务、来源引用和跨表原子提交。SQLite 支持这些正式约束，并提供易于检查、备份和导出的本地数据文件。

模型调用的等待时间远大于数据库短操作，因此写事务只覆盖领取、续期与事实提交。应用初始化启用 WAL，每个连接启用外键。正式事实继续持久化，内存只保存执行器、客户端及单次执行状态。

## 维护影响

Repository 按业务模块分开，组合根提供数据库与跨模块服务。后续结构变更使用新增迁移，已有数据处理必须明确。数据库导出包括私有信息，目标文件拒绝覆盖；新的多人部署需求需要单独审核当前单进程和连接管理条件。
