# 逐次角色回应与持久接话链

状态：角色逐次读取新发言与冻结输入的原则保留；新玩家输入和参与策略已由 [ADR-0017](0017-model-providers-and-participation.md) 及[当前会话设计](../design/conversation-and-social.md)更新。日期：2026-10-08。

群聊中，后一个角色需要读到前一个角色刚提交的内容。每个任务同时需要固定输入，保证重试和审核使用相同材料。

一次 SocialTurn 固定一次来源与观察上限，逐个尝试角色，最多提交一条发言。正式发言后建立下一次 SocialTurn，并准备新的角色快照。SocialChain 将这些安排关联到最初玩家输入，持久保存消息和任务额度。规则选择只读取资格与排序材料，选中后再由 conversations 准备角色的私有上下文。

结果登记使用明确的模块接口及当前事务，社交规划负责后续选择。当前实现将新玩家消息加入已有交流轮次，正在生成的任务继续使用原快照；新内容交给后续安排。领取、请求前检查和提交继续复核租约与业务资格。

默认选择采用规则，另有远端与本地意愿评分模式；三种模式继续使用正式来源、持久任务、共同轮次与审核边界。具体阈值和选人规则见当前会话设计。

每次发言需要新的上下文准备，增加少量数据库工作；群聊同会话生成串行执行。角色能够看到新内容，不同会话仍然并发。迁移保留旧多角色轮次的冻结输入和恢复方式，范围仅限升级前已存在的记录。

权威行为见 [会话设计](../design/conversation-and-social.md)，实际验证见 [状态](../status.md)。
