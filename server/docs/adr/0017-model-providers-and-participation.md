# 模型供应商与群聊意愿选人

日期：2026-11-20。状态：已采用。

## 背景

用户需要自行选择文本和图片供应商，并在模型开销与群聊参与方式之间选择。已有模型登记、文本网关、角色上下文、任务队列和社交轮次可以继续承担各自职责。

## 决定

文本沿用OpenAI兼容网关，客户端创建与供应商参数集中在基础设施工厂。主力由用户选择，增强默认关闭，关闭时增强任务使用主力。图片采用共同请求与结果契约，由APIMart、DashScope和MiniMax适配器转换真实协议。同步结果保存URL，异步结果保存真实任务编号。

群聊默认按规则安排候选，普通回应任务同时判断与表达。用户可选择远端或本地意愿模式，两者复用同一批次、快照、队列、租约、错误处理和选人策略。适配器分别提供JSON自评分数与二分类选项概率，结果保留分数来源。social管理轮次与最终表达安排，conversation生成、审核并发布消息，Activity管理局内行动与协调。

推荐阈值随包静态保存，未知远端使用三份远端推荐值的平均值，未知本地概率模型使用0.5。服务不进行自动校准。选人先按模型阈值筛选，以分数指数权重抽样，再作最多10%的长期参与修正。预期与实际份额按会话、模型及评分协议保存，正式发布后更新，同一消息只处理一次。

任务保存创建时的实际模型与非敏感配置，重试和重启继续使用原配置。凭据通过引用从本地文件读取，运行失败按已有恢复规则处理。

## 影响与依据

一个主力凭据可以覆盖文本功能；意愿模式增加逐角色判断费用，默认模式继续控制调用量。两类分数各用对应阈值。固定小样本适合提供推荐参数，实际角色材料变化仍会影响评分与发言质量。慢速修正保留模型分数的主要作用，帮助减少长期抽选偏差。
