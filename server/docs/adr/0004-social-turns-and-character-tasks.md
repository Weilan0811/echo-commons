# 社交轮次与角色任务

状态：生效。基线版本：`0.1.0`。

## 决定

输入批次、SocialTurn、ParticipationDecision 和 ConversationTask 分别保存输入聚合、多人回应安排、个体参与原因及实际执行。任务在规划时冻结原快照。

## 实际影响

角色可并发或重试，其他角色先提交不会改变已冻结输入。玩家窗口与角色零窗口使用共同批次结构，连续接话保持未实现。

实现依赖见 [系统设计](../design/system.md)，字段约束见 [数据库](../reference/database-schema.md)。当前差异与审核状态见 [状态说明](../status.md)。

## 背景与成立条件

真人玩家会连续输入，多名玩家输入又会交错；多个角色可以同时具备回应资格，各自成功、沉默或失败。输入收集、群体安排和角色生成具有不同的身份与结束条件。

批次明确关联某位发送者的消息，轮次合并同一受众来源，参与决定解释每个角色的状态，任务执行各自模型调用。规划时固定共享历史上限并保存独立快照，避免先完成角色改变另一角色本次输入。

## 维护影响

当前同一会话推进一个运行轮次，不同会话可以独立执行。角色完整产物立即建立 sealed 批次，界面气泡不会产生新的权威消息。连续自主聊天、模型参与评分和未来活动调度分别需要明确消费者，不能隐式绑定到聊天轮次完成。
