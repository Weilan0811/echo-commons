# 共同表达业务与独立活动表达阶段

日期：2026-11-02。状态：已实现。实现与验证见[局内表达](../design/activity-expression.md)及[06 号计划](../../../docs/archive/implementation/06-activity-implementation-plan.md#751-单元-45-实现记录2026-11-02)。

## 背景

活动模型可以同时返回游戏动作与正文，也可以只决定发言，稍后生成正文。消息保存依赖聊天任务会阻碍联合正文复用；动作成功后的表达失败则需要保留动作并独立恢复。交流安排与消息次数仍需由 social 统一维护。

## 决定

conversation 提供共同的 `ExpressionReview` 和 `ExpressionService`，普通聊天与活动复用消息权限、回复目标、受众、保存、索引及通知。正式消息明确引用聊天结果或活动结果，保留真实调用来源。

Activity 保存原活动决定及独立表达阶段，两者复用现有后台设施。动作和表达安排在一个事务中保存，正式消息和发布完成信息在另一个事务中保存；联合正文同样进入表达阶段，直接审核而不重新生成。该安排更新[游戏接入决策](0011-independent-games-and-game-decisions.md)中动作与配套发言的提交方式。

social 提供待表达完成通知，消息成功、沉默及最终失败结束原等待状态；候选排序、轮次与额度保持共同定义。事件策略只提供额外的交流机会，复用原主动接口及局内协调；概率不重复作用于已形成的决定。

当前全局逻辑队列按游戏回合、独立交流、后台整理 2:2:1 轮询领取，共享持久位置；局内回应和独立表达属于交流类别，回合配套发表直接继续原回合。领取及推进位置共同提交，继续使用原任务租约与恢复规则，详见[任务执行](../design/task-execution.md#全局逻辑队列)。同一参与身份的在执行任务及已经准备输入的恢复任务保留先后关系。事件观察使用独立的周期扫描，不等待模型任务队列空闲。

## 影响

棋盘更新可以早于配套台词到达。表达失败保留原动作和回执，恢复不会重复选择动作或生成已保存正文。独立阶段增加必要的持久进度，避免为活动另建消息业务、交流额度或模型执行中心。游戏经历与活动内心已接入按场景归段和记忆整理，见[经历设计](../design/activity-memory.md)。
