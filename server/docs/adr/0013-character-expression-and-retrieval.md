# 角色表达采用私有核查与按需检索

日期：2026-10-27。状态：已实现，待审核。证据见[表达与记忆实验摘要](evidence/20261027-expression-memory.md)，实施范围见[实施计划3.1](../../../docs/06-activity-implementation-plan.md#31-角色表达与记忆整理校准)。

## 问题

角色能识别依据缺失，公开回复仍可能承认玩家问题中的旧事。只增加边界说明、思考深度或独立审核调用，没有得到足以支持常规使用的收益。角色也需要按自己的记忆找回真实经历。

## 决定

采用同次私有核查与公开表达、缺少相关旧事依据时按需检索的方案。一次生成可以输出claims（私有核查）与message（公开消息），使用现有memory_search（记忆检索工具）后继续生成。核查记录本次相关前提、依据状态、来源和简短原因。普通表达保留直接消息形式，核查清单允许为空。依据状态包括有支持、存在冲突、未找到和不适用；保留直接消息、核查加消息两种结束结构，沉默沿用现有结果语义。

提示明确核查、查询与表达各自用途，精简无用结构注释和重复规则；仅删除事实展示中与正文重复的主题，保留事实正文与来源。共同准则要求角色相信给定记忆，允许个人日常补充，涉及他人行为与共同旧事时采用依据。缺少本次需要的旧事材料且尚未查询时先查询，无依据不能确认。

Agent输出契约保存完整私有结果。conversation在所属适配处提取CharacterMessageProposal，公开审核与提交继续使用现有消息对象。claims不成为公开消息、角色内心或正式事实，也不自动参与长期记忆整理。正式模型使用现有原生工具协议，实验JSON动作适配不进入业务模块。

新任务使用character_message.v2，支持直接消息及核查加消息；历史冻结任务保留v1。发布时，conversation_results保存v1消息结果，conversation_claims单独保存原始契约版本与核查清单；管理任务结果可以查看核查，普通消息和会话导出不携带核查。没有核查的v2发言保存空清单，保留实际输出版本。

初始上下文与工具返回提供一致的来源标识，程序检查来源的可见性与引用资格；不把编号正确当作内容得到证实。所有工具往返计入输入与请求预算。表达最多三次生成、两次查询，最后一次保留提交机会；输出额度为本轮验证的4096token上限，公开正文仍接受现有长度审核。失败恢复与费用记录复用已有设施。

4096token为默认输出额度，显式配置继续生效。初始提示沿用现有字符预算；每次实际请求另检查48000字符上限，包含消息正文、工具定义及工具协议数据。输入超过上限时明确停止，不裁剪已经得到的证据。工具请求、输出修正都占用三次生成额度，供应商内部重试关闭，任务重试沿用现有策略与记录。

social保留资格、参与判断、轮次和额度职责。本地判断模型不承担事实核查；普通回应与主动开场使用相同表达能力，触发方继续提供情景。

## 依据与取舍

自主核查提高过真实记忆找回和连续交付，同时增加调用成本。最终提示明确动作职责，精简字段说明、重复规则和重复事实主题。DeepSeek初筛与连续对话体现一定收益，复验未达到预设采用门槛。用户综合效果、成本、维护与工期决定采用，实验失败记录继续保留。完整同条件数字与采用取舍见[实验依据第5、6节](evidence/20261027-expression-memory.md#5-为什么允许按需检索)。

不增加独立前提提取服务、事实裁决模型或通用行动框架。当前仍有混合前提处理、查询选择、额外细节与格式问题；本决定不保证所有共同事实错误被消除。本地角色表达配置保留可选性，尚不作为已验证的默认替代。

## 验收

真实模型、原生工具及SQLite验证普通日常、已有事实、遗漏找回、虚构旧事、混合前提和话题切换。另验收私有核查不公开、引用资格、预算终止、失败恢复、重复提交、主动开场及两种参与配置。历史结果按原输出契约恢复，新契约和转换必须明确。
