# 模型网关与执行循环

状态：生效。基线版本：`0.1.0`。

## 决定

网关负责真实 SDK、供应商请求、超时和网络重试。Harness 负责模型工具循环、输出契约、预算与修正；任务模块负责持久恢复和提交。

## 实际影响

供应商与任务重试有不同计数和原因。更换模型不会改变权威业务写入规则，工具授权与模型可见定义使用同一能力集合。

实现依赖见 [系统设计](../design/system.md)，字段约束见 [数据库](../reference/database-schema.md)。当前差异与审核状态见 [状态说明](../status.md)。

## 背景与成立条件

网络请求、工具往返、输出修正和持久恢复发生在不同阶段。混用计数和重试原因会导致额外模型消耗、错误恢复或无法解释失败。

网关将供应商响应转成正式协议，Harness 在一次 Invocation 内管理只读工具与有限生成，业务队列保存跨尝试的状态、租约与原输入。模型可见工具定义和执行授权来源一致，模型参数不能选择其他实例的私有范围。

## 维护影响

新增供应商由登记和网关处理，新增工具由正式 ToolRegistration 处理，新增业务任务定义具体输入和审核。执行日志保留各层实际用量与失败来源，配置错误不会隐式改换模型。反思与对话可以选择不同 profile，共用模型并发额度。

角色表达、三维关系判断、材料来源规则、身份与目标字段、发言和沉默结果均由 [角色提示契约](../design/character-prompt-contracts.md) 定义。请求使用其中的完整固定正文和结构说明；每个节点只接收该节点允许的材料。
