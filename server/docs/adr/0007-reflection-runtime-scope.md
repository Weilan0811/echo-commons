# 反思运行与权威提交

状态：生效。

## 决定

反思使用有版本的固定执行图、正式来源、不可变节点产物和代码审核。段反思、连续性压缩、长期整理与视图刷新各自拥有明确的材料、结果和消费规则。活动任务采用自己的状态与提交入口。

模型只能提交候选。运行编排层先保存真实输入，在事务外执行模型调用，再在正式业务事务中复核身份、版本、观察资格、租约和来源。节点成功、阶段提交与完整运行结束分别记录。

## 实际影响

重试读取原输入并保留成功产物；部分成功通过关联原运行的补充运行完成尚未提交范围。正式结果唯一绑定运行与实际阶段，不能重复保存状态影响、事实依据或来源消费。

长期事实成功、认知失败时，可以保留实际事实和该阶段进度。认知引用在正式提交时绑定已保存事实版本，恢复不能再次执行已完成事实阶段。具体规则见 [长期整理](../design/reflection/memory-organize.md)。

## 维护边界

新增节点或消费者需要自己的真实输入、输出契约、审核、提交规则和恢复身份。已经存在表或产物类型不足以说明实际接入状态；接入和验证统一记录在 [状态](../status.md)。

共同执行对象和节点状态由 [反思执行模型](../design/reflection/execution-model.md) 定义；材料性质和长期记录由 [记忆设计](../design/memory.md) 定义；完整提示由 [提示契约](../design/character-prompt-contracts.md) 定义。状态与关系算法继续归所属角色模块。
