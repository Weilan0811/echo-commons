# 0009：HTTP 操作与统一 SSE 事件通道

## 背景

平台同时支持社群聊天与共享活动。角色消息、回应状态和活动结果由后台独立提交，客户端需要及时得知变化。固定间隔查询在没有变化时仍产生网络请求和数据库读取，并增加结果显示等待。

聊天、棋盘与讨论类活动提交离散操作，已有 HTTP 入口负责请求校验、幂等和明确响应。运行模型为本地单进程与 SQLite。

## 决定

保留 HTTP 写操作和状态查询，增加按玩家与社群范围订阅的统一 SSE（服务器事件推送）通道。聊天与活动复用事件存储、连接通知和恢复机制，各业务模块负责事件含义及玩家可见数据。

业务结果与事件引用原子提交，提交成功后唤醒在线连接。事件持久化支持断线补充；范围检查复用业务规则。角色消息通过审核并保存后完整发送。连接状态不参与业务执行成功判断。

## 影响

客户端可以取消日常页面的固定间隔查询，继续使用已有 HTTP 查询进行初始加载、历史翻页和恢复。后端需要维护事件保留、恢复位置和连接生命周期；客户端需要处理重复事件与重新同步。

操作请求沿用现有响应和错误协议，不增加双向长连接中的操作应答协议。高频连续控制玩法由活动定义专用通信需求，共同权威状态和可见性规则保持适用。

完整机制见 [实时通信设计](../design/realtime-communication.md)。
