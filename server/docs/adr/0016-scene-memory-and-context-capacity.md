# 按场景整理记忆并共享角色近期上下文

日期：2026-11-03。普通聊天的共同机制已接入；游戏正式来源与整局经历接入属于单元 4.6.2。

## 背景

角色会同时参与多个群聊、私聊及游戏。近期经历需要在场景之间产生连续影响。按全角色静默归段会让活跃群聊延后其他场景的摘要；固定携带 20 条消息、较晚才整理摘要，也会留下没有持续提供的历史范围。

## 决策

各会话及实际成员区间独立形成材料段，空闲、实际结束与容量压力通过既有反思任务处理。当前历史需要缩减时，先保存成功摘要。任务先固定来源上限，摘要等待保留原文且不领取聊天租约，完成后固定完整输入；后来生成的摘要只允许引用原范围中的材料。

角色在同一社群中共享近期经历。当前交流、临近场景、较早相关记忆按有上限的共同策略选择，继续执行原可见性。模型容量、输出预留、工具说明和完整提示共同参与计量。具体分配、排序与恢复规则见[共同上下文](../design/perspective-and-context.md#4-历史裁剪与自身思考)。

原始记录、上下文摘要和长期认识分别维护。阶段摘要和连续压缩各自保存覆盖，长期事实与认知使用原有消费者。游戏的事件输入与决策方式继续沿用现状，局内意图只服务进行中的对局；游戏来源、精彩经历和正式关闭的接入见[实施计划第 7.6.2 节](../../../docs/06-activity-implementation-plan.md)。

## 影响

容量压力下，新的判断可能等待一次摘要，增加当次响应时间并产生真实整理费用。已有摘要和覆盖可以复用，普通每条消息无需额外摘要调用。未知模型采用字节上界会保留更少的材料；配置相符的分词计量后，可以利用更多可用容量。

4.6.1 继续使用现有任务、段、来源、覆盖和消费记录，没有新增业务表或数据库迁移。4.6.2 通过迁移35保存[游戏经历](../design/activity-memory.md)的参与边界、来源引用和消费位置，继续复用原反思图。旧段和冻结输入保持原含义，后续材料从已有覆盖之外继续整理。后台消费者仍受现有并发、额度与失败恢复规则管理。
