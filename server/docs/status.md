# 能力、设计差异与审核状态

更新日期：2026-10-02；基线版本：0.1.0。design 目录定义社群、多角色和活动平台的目标业务规则与完整提示契约。此文说明当前实际能力、差异裁定及下一步代码修复计划。用户已授权按第 3 节顺序修复代码，每项验证后单独本地提交。修改记录统一见 [迁移修复记录](../../docs/09-migration-repair-record.md)。

## 0. 差异判断依据

用户已确认统一标准：确实为了多角色、Activity 或社群实现而产生的差异可以保留；其他行为和提示以原实现为准。原实现依据为改造前提交 `400defb`，必要时与首次仓库基线 `0a14ed4` 交叉核查。

每项差异分别列出保留与恢复的部分。改变目录、服务接口和数据库布局不意味着可以重写角色表达、事实判断、关系算法或失败语义。原实现未完成的能力保持未完成；原文档提出的目标不能直接登记为迁移丢失的已实现能力。字段结构和流程能够正常运行也不能代替原行为核查。

## 2. 已确认差异与待查项目

### D10：原始提示内容未逐字保留——P0 最高优先级

对照改造前提交 `400defb`，已确认对话指导、输出说明、反思节点细则、上下文表达、正式工具提示及部分修正提示被删除或改写。人物资源正文与初始记忆保留，不能据此认定模型实际提示一致。完整核查及十五项 P0 差异见 [提示逐字核查](../../docs/07-prompt-preservation-audit.md)，原文和完整比较证据一并保存。

本项优先修复。保留真实发送者、社群和实例范围、关系 target、回复来源及合法沉默所需的结构扩展；恢复七段对话指导、输出表达、第一人称、六类节点细则、记忆来源判断、工具说明和修正文字。关系从单目标变为多目标可以改变字段结构和数量范围，其三维判断及数值算法保持原规则。

完整固定正文、当前多角色字段及示例在 server 内的 [角色提示契约](design/character-prompt-contracts.md) 保存。对话字段直接定义 thought、utterance、可选 reply_to_message_id 和独立 silent 结果；关系变化每项直接定义 target、dimension、direction、level。字段说明和示例一致，修复代码时按这份确定的契约实施。额外字段结构说明不能替代业务文字；扩大查询长度、统一放宽 NoOp、将常驻背景或前驱分析当作新证据均不属于必要扩展。

### D01：对话没有读入自身历史 Thought

ConversationContext 读取消息、状态关系、resident 和 digest，没有读取 Thought；ObservedMessage 与 MemoryContext 没有对应内容。提交和段反思保存、读取 Thought，不能证明对话用途保留。目标见 [上下文](design/perspective-and-context.md)。整改需明确历史关联、预算、归属及清除后的实际快照断言。

### D02：冻结连续性批次可以 NoOp 结束

ReflectionReview 普遍允许 no_op；GraphReview 对 NO_OP 提前允许；Facts 未发现 digest 时传空内容，MemoryContinuity 返回而不生成 digest；图仍可 approved 并结束。这与 [连续性设计](design/reflection/continuity-compress.md) 的必需产物冲突。整改应恢复逐图许可和真实拒绝断言。

### D03：失败流程重新启动丢失；部分成功后的补做保持未实现

改造前 Coordinator 加载失败运行的输入，存储服务重新激活失败节点及图运行。当前再次调度仅返回 failed 记录，真实 SQLite 验证确认没有重新开始。这是迁移造成的退化，需要恢复失败流程的正式重新启动入口，保留冻结材料和已成功产物。

partial 后另建恢复运行、只补做失败可选分支，改造前没有完整接入，继续保持未实现。过期租约恢复已经存在。

### D04：状态版本行为已核实；保存前文字处理遗漏

模型候选不携带模型读取时状态版本，改造前同样如此。事实写入使用事务内最新记录，当前事务以 BEGIN IMMEDIATE 执行，版本递增、活动状态 24 小时失效及失效后不恢复旧状态已通过真实数据库验证。撤回新增模型候选版本协议的要求。

改造前 StateFactHandler 保存 candidate.value.strip()；当前直接保存 value。恢复保存前去除首尾空格，其他已经验证正确的状态行为保留。

### D05：关系漏算怀疑已撤回

当前按目标分组，一次处理该目标全部维度。真实 SQLite 验证同一目标好感和信任均从 50 变为 50.5，重复提交没有重复加分。图级审核限制同一目标维度唯一，候选与事实、审核结果同事务提交；已有图结果阻止同图再次消费不同候选。当前正式调用链没有确认的漏算问题，保留多目标分组，不新增重复内容保护或来源身份框架。

### D06：轮次、系统来源和意图存在契约差异

这项包含不同来源的四个问题，分别裁定：

| 项目 | 依据与当前差异 | 处理决定 |
|---|---|---|
| SocialTurn.pending | 社会轮次是多角色新增对象；当前原子规划直接建立 running 或 completed，SQL 仍允许 pending | 保留原子规划和现有三个正式轮次状态；清理 SQL 与类型不一致的 pending 许可 |
| system 消息来源 | 原 Message 支持 system 来源；当前 ActorRef 只支持玩家和角色，SQL 仍允许 system 消息 | 玩家、角色成员身份可保留；恢复旧代码已有的系统消息数据表达；旧源码没有实际自动发送入口，保持通知流程未实现，不让系统成为玩家或关系目标，不为尚未实现的 Activity 编写通知流程 |
| EventRef | 原改造方案提出通用引用，当前使用具体来源身份与版本 | 保留明确来源的具体类型；活动接入时定义活动结果引用，不提前加入无消费者的通用层 |
| intent | 新快照有默认空字段，当前没有填充和消费；改造前源码没有意愿生成或消费流程 | 保持未实现，不新增意愿类别或生成流程 |

人物可用状态和任务失败分别保存。原项目专用状态的已批准删除范围继续遵守，代码状态和 SQL 允许值必须一致。

### D07：关系资格有规则，消费者只有普通互动

原段反思 RelationshipFactHandler 同样固定 interaction；当前未增加其他类别消费者，属于原有边界。保留 support、conflict、commitment 的领域规则和朋友、依恋资格，保留多目标关系身份；本轮不新增支持或承诺分类器。数值公式、步长、初始化和资格继续按原算法验证，完整说明见 [角色事实](design/character-state-and-relationships.md)。

### D08：长期文档完整性与独立性

长期设计已分离对象生命周期，补回事实与回忆判断、逐节点职责、材料投影、业务条件及运行例子；原提示全文保存在 server 的正式设计中。开发说明继续索引源码，设计正文解释完整意图。用户确认此次修订方向，修订内容供阅读核验；文档检查不能证明运行代码已经符合设计。

### D09：省略路径与字段分组

新 TOML 分组和包内人物资源属于新平台配置布局，可以保留。原加载器按明确分组读取，文件相对路径有明确基准；当前省略路径依赖工作目录，部分字段按最终名字验证，可能接受放错组的字段。这些歧义没有服务多角色或社群需求。

下一步保持新分组、包内资源和用户模型登记，恢复明确的组约束与路径解析规则。显式路径及省略的默认文件路径以设置文件目录解释；默认模型登记和密钥文件名、数据库目录应与正式模板一致，避免重复拼接 config。包内人物资源不转换成外部路径。实际现状继续如实保留在 [配置参考](reference/configuration.md)。

### D11：反思节点的信息投影退化

原 NodeInputProjector 按节点选择 identity、character_state、relationship_state、memory_context、materials 等字段。当前 prepare_node_input 保存整个 graph_snapshot，project_node 向所有模型节点发送完整 self、memory、environment 及材料。

完整图快照持久化可以保留；它适合社群内独立实例和来源冻结。模型输入仍应恢复原逐节点投影，关系节点只增加真实目标和对应关系，材料只增加发送者及必要可见范围。字段选择不能因为多角色而全部取消。此项与 D10 一起优先修复，目标矩阵见 [反思执行](design/reflection/execution-model.md)。

## 3. 已授权的逐项修复顺序

目标是恢复已实现行为，同时保留多角色、社群及 Activity 必需扩展。每项完成后验证、更新本文件与同一份 [修复记录](../../docs/09-migration-repair-record.md)，使用英文提交信息单独本地提交。不得将原本未完成的能力作为本轮新功能实现。

| 顺序 | 修改内容 | 完成条件 | 状态 |
|---|---|---|---|
| R01 | 恢复对话、反思固定提示、工具及修正文字 | 固定正文逐字验证，必要结构扩展有明确记录，真实模型输入符合提示契约 | 已恢复；8 项本地验证通过，真实模型查询场景未通过，R09 继续验证 |
| R02 | 恢复逐节点信息选择 | 各模型节点只获得矩阵规定的信息，背景和可引用来源分开 | 待执行 |
| R03 | 恢复自身历史内心记录 | 与自身发言关联，其他角色无权读取，清除与冻结输入规则有效 | 待执行 |
| R04 | 恢复必需摘要审核与提交 | 有实际材料的段和连续性批次不能无摘要成功；拒绝不推进消费 | 待执行 |
| R05 | 恢复失败反思流程重新启动 | 正式调度重新激活失败运行，复用冻结输入和成功产物，旧尝试不能提交 | 待执行 |
| R06 | 恢复状态文字处理 | 保存前去除首尾空格，版本及期限保持现有正确行为 | 待执行 |
| R07 | 修正轮次状态与系统消息来源 | 类型与数据库一致；系统来源不取得成员或关系资格，不新增通知流程 | 待执行 |
| R08 | 修正配置字段分组与路径 | 换启动目录不改变同一设置文件的路径解释，错组字段明确拒绝 | 待执行 |
| R09 | 组合验证与实际文档更新 | 必要真实存储、任务、恢复及模型验证；参考文档和实现状态准确 | 待执行 |

D08 的文档重建已提交于 744a204，实施时只随对应代码更新长期文档。D05 无修复任务。日记、视图、partial 补做、关系支持和承诺消费者、意愿生成、统一事件引用及 Activity 执行继续保持未实现。用户模型登记、密钥和业务数据保留。

## 4. 证据与验证范围

2026-10-02 文档规划前快速测试为 84 passed、9 deselected。先前九项真实模型场景和源码目录外安装验证使用真实 DeepSeek 路由；生产 strong 路由的 GLM 曾真实 120 秒超时，该次不计通过，用户模型登记未改动。此轮文档重建未重新请求模型或启动服务。

[验证指南](guides/verification.md) 保留 A01—A32 和此次修订后的必要断言。快速测试通过只证明已有断言，不能证明提示、Thought 和连续性要求已保留。按第 3 节已授权顺序修复代码并执行真实验证。日记、视图、partial 补充恢复及尚未实现的活动流程保持原范围。
