需求依据为前端工作树 frontend/docs/02-backend-interface-gaps.md 的 3.3、3.4，以及本轮确认的测试清理和角色插画规格。生成任务保持单图，用户图片采用固定用途规格；官方素材由前端发布，窄屏背景使用横图中心裁切。活动接口、记忆索引响应类型、玩家个人头像、聊天图片和角色表情差分分别属于其他任务。

## 2. 计划接口

以下路径为实施安排，完成后以生成的 OpenAPI 与接口参考为准。

| 方法与路径 | 内容 |
|---|---|
| POST /internal/maintenance/cleanup | 已实现 community_ids、draft_ids、player_ids，dry_run 默认 true；返回按表数量、missing、阻止对象及保留资源；asset_ids 和文件清理随资产模块扩展 |
| POST /api/communities | 保留现有请求，增加可空 cover_kind、cover_ref |
| PATCH /api/communities/{community_id}/appearance | player_id、expected_version、cover_kind、cover_ref；社群成员设置或清除封面 |
| PATCH /api/communities/{community_id}/characters/{character_id}/appearance | player_id、expected_version、可空 avatar_asset_id；设置覆盖或恢复默认，返回展示版本与公共头像 |
| GET /api/assets/generation-styles | 返回编号、展示名、说明及适用用途，不暴露供应商配置 |
| POST /api/assets/images | player_id、purpose 和文件表单；按用途缩小并保存标准 WebP 与展示档位，角色上传先返回插画资产 |
| POST /api/assets/{asset_id}/avatar-crops | player_id、client_request_id、x、y、size；按完整插画像素坐标保存方形裁剪，返回独立头像资产 |
| GET /api/assets | 按所属玩家与用途分页列出资产 |
| GET /api/assets/{asset_id} | 所属玩家读取元数据、规格和图片地址 |
| GET /api/assets/{asset_id}/images/{variant} | 读取标准图或指定展示档位，返回实际宽高对应的 WebP 文件 |
| DELETE /api/assets/{asset_id} | 所属玩家删除未引用资产，处理中或被引用时返回冲突 |
| POST /api/image-generations | player_id、client_request_id、purpose、style_id、scene_context，草稿编号及 revision 或明确描述；返回持久单图任务，规格由用途决定 |
| GET /api/image-generations/{generation_id} | 所属玩家查询状态、asset_id 或明确错误 |

角色生成用途为 character_illustration，完成时只返回插画 asset_id，输出 illustration.webp：1080×1350、带完整背景的胸像到半身插画及 540×675 预览档。建议初始选区取插画上部，x=0、y=0、size=1080；公共构图提示预留头顶、左右和发饰空间，脸部位于头像选区中央附近，保留少量肩颈与虚化环境。

人物默认表情与姿态安静自然，四周压暗，视觉重心在画面中上部；人物光影与选定场景一致。前端场景清单提供 scene_context，包含 preset_key、time_of_day、lighting、palette、background_description；后端冻结这些材料。公共提示只维护构图和光影一致要求，画风配置维护笔触与上色，时间和环境由场景预设提供。

作者在前端确认方形框的取景后，后端保存 character_avatar 派生资产，导出 512×512 和 256×256 两档 WebP。裁剪坐标基于 illustration.webp 实际像素，复核边界和请求重复；完整插画保留，头像保存来源插画及裁剪区域。选定头像时通过来源关联同时更新人物插画与头像展示，删除检查包含来源引用。

官方角色的 illustration.webp 和 avatar.webp 按相同规格制作，默认头像在素材制作阶段逐张检查后随前端发布；运行时直接展示成品。官方素材及清单不进入后端资产库，本轮后端提供引用字段与使用说明。

封面与聊天背景的用途提示分别实现：community_cover 按明确提交的世界描述生成横幅，允许具体明亮的场景，预留标题区域；chat_background 按独立环境材料生成中性横图，中部暗且空、细节集中在边缘，中心裁切以及压暗模糊后仍适合阅读。聊天背景不自动读取社群世界设定。

用户封面固定为 1600×600，展示档位宽度为 768、1536；用户聊天背景固定为 1920×1080，只有横版标准档。官方封面 3200×1200、官方聊天背景 3840×2160 随前端发布。后端数据继续使用单个资产及其多档文件，每个生成任务保存一个供应商 task_id，成功返回一个 asset_id。

草稿创建和修改增加裁剪头像资产输入，沿用草稿 revision；与外部 avatar_url 互斥。定稿保存资产身份，公开 avatar_url 和 illustration_url 在读取时生成；官方模板可提供随前端发布的插画地址，无关联插画时 illustration_url 为空。封面同时为空表示清除；社群所有相关公共响应提供选择字段。角色覆盖使用独立展示版本，保留原可用状态版本含义。

封面和角色展示实际变化分别增加 `community.appearance_changed` 与 `character.appearance_changed`，内容只含社群和相关对象编号；沿用成员校验、同事务事件保存、提交后唤醒和事件数据生成检查。更新事件枚举、数据库 kind 约束及投影，不改变既有事件含义。

缺少生图凭据在提交请求时返回明确的环境不可用错误，公开字段和 HTTP 状态与现有创作不可用错误风格一致。仍被引用、版本过期和正在执行的清理对象返回 409；严格请求和图片格式、尺寸检查使用已有错误转换方式。

清理请求至少提供一个对象编号，不接受全库清空、名称匹配或客户端 SQL。预览返回存在性、分类数量和阻止执行的原因；执行时重新计算并复核范围。不存在的对象计入 missing，相同请求再次执行不影响其他对象。

社群整体清理包括成员、角色实例、会话、消息、轮次、任务、记忆、搜索索引、阅读位置、执行记录及实时事件。追踪按实际关联选择。草稿和玩家分别指定；草稿清理包括候选与固定人物资源，范围外实例仍使用该资源时拒绝。指定玩家仍属于其他社群，或拥有未选择的草稿、人物资源、资产及生成任务时拒绝。

目标社群必须暂停且没有在途任务，草稿或资产的生成调用进行中也拒绝。普通数据库连接保持外键启用，相互引用可以延迟至事务提交检查；一次事务失败全部回滚。提交后唤醒被删除社群的连接，由资格检查结束订阅，不新增指向已删除社群的事件。响应说明诊断文件保留范围；实现完成后具体使用方法登记在管理接口参考。

路径相对 server/src/echo_commons/，配置和测试路径另行注明。

|---|---|
| modules/assets/domain.py、contracts.py | 资产、用途标准图与展示档位、插画与裁剪来源、场景输入、单图任务状态和依赖端口 |
| modules/assets/service.py、repository.py | 归属、分页、引用、重复请求和删除 |

| modules/maintenance/contracts.py、service.py、repository.py | 请求与响应、范围选择、运行检查、引用复核和关联删除；数据库部分已实现 |

| resources/assets/generation_styles.yaml | 生图风格及描述，使用已有 YAML 解析库 |

| infrastructure/database/sql/ | 新增迁移：封面、展示版本、资产及引用、生成任务、事件种类约束 |
| server/config/ 和包内配置模板 | 非秘密生图路由与参数；model-secrets.example.toml 增加 apimart 空值引用示例 |
| server/tests/infrastructure/ | 真实 SQLite、文件、HTTP 上传与读取、删除和任务状态验证 |

正式默认资产目录为 server/data/assets/images，图片目录以 asset_id 区分；文件命名与规格遵循 [资产设计](design/image-assets.md#2-上传与文件规格)。上传和下载只在临时目录保留输入文件；超过用途规格时等比缩小，转码成功后删除输入文件，持久目录保存用途标准图及展示档位。角色插画上传上限 5 MiB，封面与背景上限 8 MiB；小上传图不放大。

供应商请求固定 n=1、resolution=1k，size 按用途设置为 1080x1350、1600x600 或 1920x1080；将固定参数和完整提示保存到任务。检查真实返回尺寸及比例，足够大的结果导出标准图与对应展示档位，不足或比例不符时登记明确错误。角色生成完成后返回插画 asset_id，玩家确认裁剪后通过独立请求取得头像 asset_id；上传与生成复用相同图片处理和存储入口。

配置支持资产目录、生图并发、查询间隔、请求期限和任务总期限。生图默认并发 1、每 5 秒查询、请求期限 30 秒、任务期限 900 秒；公开请求不接受分辨率参数。

## 5. 验证与密钥边界

不读取或修改实际 model-secrets.toml，也不运行会间接加载该文件的默认应用或测试。所有本轮验证显式指定独立临时配置和空凭据文件；原有路由、数据库与密钥保持完整。

- 清理：真实创建两个社群，验证目标删除、范围外保存、草稿及人物软引用、玩家跨社群引用、在途拒绝、事务回滚、重复请求和 SSE 关闭。
- 资产：用 Pillow 生成实际图片文件并通过 HTTP 上传，验证内容格式、用途上传上限、超过目标尺寸时等比缩小、小图不放大、输入文件移除和持久目录只保留标准 WebP 与展示档位。核对插画 1080/540 档、头像 512/256 档、封面 1600 标准图及 768/1536 档、背景 1920×1080 单档；验证资产响应的实际宽高与读取文件一致。角色上传只创建插画；通过正式裁剪接口保存头像，核对选区、坐标边界、重复请求及来源保留。拒绝非图片和 SVG，检查归属、来源引用、删除与中断清理。图片文件是实际测试输入，不替代供应商生成结果。
- 业务：社群预设编号不产生文件，创建及修改字段一致；旧空封面和外部头像保留；草稿定稿、复制、实例覆盖及公共身份读取使用同一引用规则；旧版本修改失败。
- 生图：公共构图、画风与 scene_context 分别通过正式输入组装；验证角色夜间和日间材料、封面世界描述、聊天背景中性环境与中央留白要求进入各自提示。检查单图任务、固定用途尺寸、resolution=1k、同输入重复请求、成功时只返回一个 asset_id；公开请求拒绝分辨率字段。生成角色插画后，确认裁剪才创建头像。缺少凭据使用真实空配置验证不可用响应；供应商响应按正式类型处理，不使用 mock 或预设成功返回。精确像素请求、实际返回尺寸与图片质量，通过真实供应商调用验收；角色取景检查头部与发饰，背景检查中心裁切及压暗模糊后的阅读效果。
- 交付：相关非模型回归、静态检查、生成契约、数据库与源码参考、文档链接和 wheel 包资源；不生成前端类型或运行前端构建。

没有密钥时不能完成真实供应商生成、供应商任务重启恢复及结果下载的成功路径验收。交付时如实登记这几项待验收；用户填入密钥后在独立测试环境验证实际生成、下载、规格、幂等和重启查询，不使用虚构结果补充验收。
