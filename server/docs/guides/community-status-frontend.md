# 社群运行状态与封面接入

新社群默认暂停，创建、加入、选择和打开页面均不自动启动。前端已通过独立详情页提供运行状态与封面修改；页面组织、缩略图预览和键盘交互见 [社群页面设计](../../../frontend/docs/03-page-design.md#33-社群操作)。本文定义请求、版本与缓存处理。

## 1. 读取与修改状态

读取 `GET /api/communities/{community_id}?player_id={player_id}`，返回 `PublicCommunityView`。正式状态与玩家操作许可分别定义在 [社群规则](../design/identity-and-communities.md#6-读取与变化边界)；前端按 `capabilities` 提供操作，并使用 `status` 与 `state_version`：

| 后端值 | 展示文字 | 可执行操作 |
|---|---|---|
| `paused` | 已暂停 | 启动社群 |
| `active` | 运行中 | 暂停社群 |

状态修改请求：

```http
PATCH /api/communities/{community_id}/status
Content-Type: application/json
```

```json
{
  "player_id": "lin",
  "status": "active",
  "expected_version": 0
}
```

暂停时将 `status` 改为 `paused`。`expected_version` 必须取自最近读取的 `state_version`，不能固定填零。社群列表卡片不含版本，修改前需要社群详情。完整字段以 [OpenAPI](../reference/openapi.json) 和 [接口参考](../reference/http-api.md) 为准。

成功返回 200 和最新的完整 `PublicCommunityView`。状态发生变化时版本增加；版本有效且状态没有变化时返回原对象，版本不增加。封面修改使用 `PATCH /api/communities/{community_id}/appearance`，提供 `player_id`、`expected_version`、`cover_kind` 和 `cover_ref`；两个封面字段同时为空时清除，官方封面使用 `preset` 与预设编号，资产封面使用 `asset` 与资产编号。两类修改共享社群状态版本。

| 响应 | 前端处理 |
|---|---|
| 200 | 使用返回对象更新社群详情缓存，并刷新已加入社群列表、相关会话列表和任务展示 |
| 409 | 社群版本已经变化；重新读取详情并提示用户重试，不自动覆盖其他操作 |
| 404 | 社群不存在、玩家不存在或玩家不属于社群；展示友好提示并刷新当前社群信息 |
| 422 | 请求格式错误，例如状态无效、版本为负数或包含未知字段 |
| 网络错误 | 保留最后确认状态并展示错误，重新读取后允许重试 |

当前为本地玩家身份模式，社群成员均可修改运行状态，权限沿用现有 `player_id` 规则。

## 2. 界面与请求实现

- 创建时显式传入选定时区；创建成功后打开返回社群的详情，保留暂停状态并提供启动与进入操作。
- 封面预览保存为页面输入，选择图片时不写入。放弃编辑恢复已保存封面；失败保留选择。原封面为资产时，不自动转换为官方预设。
- 封面和状态共用 `useUpdateCommunity`，请求与缓存刷新完成之前禁止提交下一次变更；成功响应先取消同一详情的旧查询，再写入权威返回值，最后刷新目录与相关管理查询。
- 修改失败后重新读取社群详情，以便下一次操作携带正确版本。切换详情时清除前一个社群的选择和操作错误，缓存与请求绑定实际玩家和社群。
- 状态与错误均通过现有展示组件呈现，内部错误类型保留给管理端。请求类型从 OpenAPI 生成，业务字段不在页面重新定义。

暂停与恢复对后台任务的具体影响见 [社群运行规则](../design/identity-and-communities.md#5-世界时间与运行时间)，界面不应承诺暂停能够撤销已经产生的模型用量。

## 3. 验证与测试数据

使用真实后端和独立临时数据库验证以下流程：

1. 新建社群返回 `paused`，页面显示“已暂停”和启动入口。
2. 启动后返回 `active`，页面显示“运行中”和暂停入口。
3. 暂停后刷新页面、离开再进入，仍保持暂停；进入页面不自动启动。
4. 版本过期时展示冲突，重新读取版本后可以再次操作；非成员修改返回 404。
5. 封面预览不修改数据库，放弃恢复原图，保存后刷新保留；连续修改按最新版本执行，外部修改导致冲突时保留选择并重新读取。
6. 原有聊天测试创建社群后，凡需要角色回应或后台记忆处理的用例，应通过状态接口明确启动，再继续原流程。

已有测试准备流程如果默认社群立即运行，需要增加唤起请求。测试结束清理临时数据库，避免向日常数据库积累社群和后台任务。
