# 扩展模块与能力

先读所属设计，再按 [源码导航](../reference/source-map.md) 找入口。每项扩展都明确输入、权限、输出、审核、事实归属和验证；不把新业务塞进通用对象的大量可选字段。

| 扩展 | 修改入口 | 必要检查 |
|---|---|---|
| 人物模板 | resources/identity 或配置外部根、模板 manifest | 完整资源合法、绑定版本、两个独立实例初始化 |
| 只读工具 | 正式服务、agents/harness/tools、能力解析与 app 组合 | 模型定义与授权一致、真实读取权限、进展与预算 |
| 输出契约 | 具体业务契约、OutputRegistry、输入动作空间及投影 | 正式解析、非法字段拒绝、用途和范围一致 |
| 反思节点 | reflection 图定义、输入投影、行动标准化、依赖及聚合 | 前驱绑定、证据映射、必需/可选失败与 NoOp |
| 反思消费者 | reflection 图审核和 facts、所属领域服务与 Repository | 精确覆盖、来源版本、消费与事实原子性 |
| 持久任务种类 | 所属模块的 queue、handler、快照、commit，execution 注册及生命周期 | 租约代次、恢复、取消、独立业务完成 |
| 活动 | 新 activities 模块、perspective 活动读取、活动任务与合法动作 | 固定行动资格、聊天并行、旧版本拒绝及精确来源 |
| 数据字段 | 新迁移、Repository、业务转换、字段参考生成 | 已有数据处理、真实约束、回滚和重建 |

## 一次工具扩展

先由对应模块提供只读服务，输入明确角色范围和观察边界；再定义工具参数及正式返回材料；登记模型工具、实际执行和进展提取器；让模板和本任务明确许可；最后通过真实数据检查未授权、空结果、重复材料及正常读取。不允许工具直接写入活动或关系事实。

## 一次反思扩展

先完整说明该图的触发、来源、拓扑、逐节点字段和事实消费者，再登记具体类型和运行流程。日记、视图已有 [完整设计](../design/reflection/README.md)，接入需完成各自列出的材料、调度、审核及事实步骤，不以新增节点名称作为完成。

## 文档和验证

业务变化更新权威设计、HTTP 或资源契约、配置、状态与相应 ADR。运行文档生成检查；按实际影响验证正常和失败路径，模型生成使用真实供应商。公开接口只提供当前实际入口，目标扩展明确标为待实现。

角色提示扩展以 [完整提示契约](../design/character-prompt-contracts.md) 为依据。群聊发送者、关系目标和活动动作有明确结构用途，新增它们时遵守提示契约中的角色表达、事实判断和示例。节点选择材料使用所属投影矩阵，执行状态使用 [对象归属](../design/object-lifecycles.md)，避免扩展时重写已有规则。
