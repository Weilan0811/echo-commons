三份人物正文分别承担以下职责。叙述可以连续成文，也可以按内容分段；篇幅由已有材料和表达需要决定，不为凑字或追求简短删去人物特征。

profile 写这个人是谁、怎样生活、在意什么，以及什么条件会影响感受和选择。从多件经历中概括稳定特点，保留能说明人物的具体细节。经历用于解释现在的处境和特征；完整事件经过保留在 story，逐人的关系经过保留在 relationships。已有的重要事实与明确限制保持原意，不把人物简介扩写成履历或关系清单。

voice 写实际能够听出、读出的说话方式：自称和称呼、措辞、句式、节奏、停顿、语气，以及不同情景下怎样变化。只选本人说的话，从不同表达中概括习惯，并保留少量有具体内容、能体现不同特点的中文例句。用自然的描述交代语气和情景；网页出处、章节编号、游戏界面标签和外文对照留在参考资料中，不写入正文。不要添加“以下例句取自原文”等说明，也不把例句当作新发生的共同经历。只有性格描述时，可以按作者允许的范围补充表达示例，补充来源在 changes 中说明。标志性口癖按本人材料保留常用频率，兴奋、害羞、认真等变化也需体现，不能把所有人写成同样克制的口吻。篇幅由表达需要决定。

relational_dynamics 写这个人的一般社交形式：会怎样主动接近、回应他人、表达关心、建立或失去信任，面对陌生人、熟人、亲近者以及分歧时有哪些有条件的倾向。通过具体互动说明倾向，并保留人物自身的变化可能。对某个具名人物的评价、亲近程度、共同过去与关系进展保留在独立关系材料及关系状态中；本篇只写一般倾向，不设置对某个具名人物的专门描述。可以从具体关系经历中理解一般倾向，但不能把一个对象的待遇推广成对所有人的规则。特定称呼确实体现语言特征时放入 voice，必要的身份背景可简要进入 profile。

输入里的 description、story、relationships 和采访是创作依据，各自原文会单独保存。整理三份正文时按上述职责选择有用的信息，无需把每条材料复制进正文。具体人物的初始态度由关系初始化处理，运行后的态度变化由关系状态维护。

完成后核对：人物特征是否具体，已有的代表性台词是否保留，相处方式能否用于理解面对一个新认识的人时的表现，具体人物关系是否仍留在其所属材料中。三份文档可以互相补充，避免重复列出同一份经历和关系。
